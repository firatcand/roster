# Issue #372 implementation plan — drain function-registry validation under pipefail

## Ticket

- GitHub: `firatcand/roster#372`
- Branch: `feat/372-fix-function-registry-pipefail`
- Type: contained scaffold-script correctness regression

## Outcome

Make `is_valid_function` reliable when Bash runs with `pipefail` and PyYAML is
unavailable. A valid function must be accepted regardless of its position in a
multi-entry registry, unknown functions must still be rejected, and malformed
slugs anywhere in the producer stream must still make validation fail.

The shared primitive is called by `new-agent.sh`, `audit-agent.sh`, and
`create-function.sh`. In the last caller, a false negative can invert the
"already registered" guard and allow execution to continue until a later
filesystem check.

This ticket changes only the shared function-registry primitive, its shell
regression coverage, the CI step that enforces that documented gate, and the
user-facing fix note. It does not change the v2 workspace authority, introduce
a runtime executor, or alter how hosts interpret plans.

## Root cause

The fallback implementation of `read_functions` is a streaming Bash producer.
`is_valid_function` currently pipes it into `grep -Fxq`. When an early entry
matches, the consumer exits without reading the rest of the stream. Under
`pipefail`, the producer can receive `SIGPIPE` and return 141, so the whole
pipeline reports failure even though the requested function exists. A last-entry
match succeeds only because the producer reaches EOF before the consumer exits.
Removing only `-q` is not portable: GNU grep also enables early-match exit when
its output is redirected to `/dev/null`. The fix must therefore remove the
producer/consumer pipeline rather than tune grep flags.

The failure is deterministic in the forced fallback path: a first-entry match
returns 141 while a last-entry match returns 0. On the affected development
environment, the existing scaffold suite is already red at 22 passes and 13
failures. GitHub CI currently omits `pnpm test:scaffold-scripts`, and its Ubuntu
runner normally has PyYAML, so both the suite and fallback path were absent from
the branch-protection signal.

Early consumer exit is also incompatible with complete producer validation. A
malformed slug after a matching slug cannot be treated as a safe success, though
the end-to-end caller may perform another registry read that makes this case a
defense-in-depth assertion rather than the discriminating regression trap.

## Implementation

1. Materialize and validate the full registry before performing the exact-line
   search:

   ```bash
   is_valid_function() {
     local fn="$1" registry
     [[ "$fn" =~ ^[a-z][a-z0-9-]*$ ]] || return 1
     # Read the registry fully before matching; an early-exiting pipeline can
     # SIGPIPE read_functions and reject a valid first entry under pipefail.
     registry="$(read_functions 2>/dev/null)" || return 1
     grep -F -x -q -e "$fn" <<< "$registry"
   }
   ```

   The assignment and `local` declaration stay separate so command-substitution
   failure is not swallowed. The canonical slug regex rejects empty,
   leading-hyphen, and newline-bearing input before any filesystem consumer can
   use it. `grep -F -x -q` preserves exact quiet matching and `-e` prevents
   option parsing even if the guard is later refactored. Because
   `read_functions` completes before grep starts, producer errors and malformed
   later slugs propagate even when the caller has not enabled `pipefail`. This
   deliberately strengthens failure propagation; all three callers were audited
   and none relies on accepting an early match from a malformed registry.
2. Add deterministic regressions to `test/new-agent-slash-only.sh` that force the
   no-PyYAML fallback even on development and CI machines where PyYAML is
   installed. Reuse the repository's proven `PYTHONPATH` poisoning pattern from
   `test/audit-agent-guideline-refs.sh`: a scoped `yaml.py` raises `ImportError`
   while leaving the real interpreter and shell tools visible. Extend the local
   subprocess helper only as needed to pass that scoped environment.
3. Add direct shared-library coverage that sources `functions.sh` under
   fallback forced and pins exit status for first-, middle-, and last-entry
   matches plus unknown, empty, leading-hyphen, and newline-bearing inputs. Use
   roughly 5,000 deterministic synthetic slugs with the target first. The
   current bug already reproduces on the four-entry registry; the larger fixture
   additionally guards future buffered producers by exceeding typical pipe
   capacity on both BSD and GNU systems. Also prove a malformed tail fails with
   `pipefail` disabled, demonstrating producer errors are propagated before
   matching.
4. Exercise the real `new-agent.sh --slash-only` path against a multi-function
   fallback registry and prove first-entry `gtm` succeeds and an unknown function
   fails without timing out. Keep a valid first entry followed by a malformed
   slug as defense-in-depth coverage, without claiming that this end-to-end case
   alone distinguishes the old and fixed implementations.
5. Add `pnpm test:scaffold-scripts` immediately after `pnpm test` in
   `.github/workflows/ci.yml`. This makes the documented required phase gate true
   in branch protection and forces the new fallback regression on Ubuntu even
   when PyYAML is installed. Leave `publish.yml` unchanged: tagged releases are
   cut from already-protected `main`, and expanding release-workflow policy is
   outside this regression ticket.
6. Align `CONTRIBUTING.md` and mirrored `GEMINI.md` guidance with the
   already-canonical full phase gate. Update the contributor CI description to
   list the actual verify-job steps, including `test:scaffold-scripts` and
   `e2e:schedule`; README, SPEC, AGENTS, CLAUDE, and roadmap guidance already
   declares the phase gate unconditionally.
7. Add a concise `[Unreleased]` changelog entry describing valid-function
   rejection on no-PyYAML systems and the fix.
8. Preserve all existing PyYAML-path and malformed-slug coverage. Do not change
   `read_functions_with_metadata`, `audit-repo.sh`, or
   `test/audit-agent-guideline-refs.sh`.
