# Issue #342 implementation plan — sparse workspace registry and scaffolding

## Ticket

- GitHub: `firatcand/roster#342`
- Forge task: `P1-T02`
- Branch: `feat/342-build-sparse-workspace-registry-and-scaffolding`
- Type: foundation / breaking v2 workspace contract

## Outcome

Replace Roster's eager workspace forest with the smallest agent-facing authoring
surface:

```text
roster.yaml
ROSTER.md
```

Claude Code or Codex can then ask Roster to create one function, agent, plan,
subagent, guideline, tool-use definition, or lesson at a time. The authored
hierarchy remains explicit, while `roster discover --json` returns a flat,
deterministic list of compact qualified records. Roster creates and retrieves
structure; it does not interpret plans, execute tools, schedule work, or own
human decisions.

## Decisions applied

The ratified SPEC resolves this ticket without a new product fork:

1. **Canonical registry is hierarchical, discovery is flat.**
   `roster.yaml` registers function roots. Each `function.yaml` registers its
   function guidelines and agents. Each `agent.yaml` registers its plans,
   subagents, guidelines, tool-use definitions, and lessons. Discovery follows
   only those declarations; it never adopts arbitrary files through directory
   scanning and never creates a second committed or generated authority.
2. **Use the physical layout printed in `spec/SPEC.md` for this ticket.**
   Function- and agent-scoped guidelines are supported. Tool-use definitions
   and lessons live under their owning agent; a plan scope may be expressed in
   their metadata. Workspace/function tool-use precedence and any additional
   symmetric tool roots remain #347's schema decision rather than an
   undocumented expansion here; additional workspace/function lesson roots
   remain #358's lifecycle decision.
3. **Expose one explicit, agent-friendly scope grammar.**
   Existing canonical target syntax remains `gtm/social-manager` for agents
   and `gtm/social-manager#opportunity-discovery` for plans. Scaffold creation
   uses an unambiguous local ID plus `--scope kind:qualified-id` for every owned
   kind. `--function` and `--agent` remain documented convenience aliases that
   normalize into the same scope value rather than separate semantics.
4. **Markdown records have versioned bounded frontmatter.**
   Guidelines and lessons declare their ID, purpose, kind, and structured scope;
   file paths and embedded identities must agree.
5. **`ROSTER.md` is generated product bootstrap, not company policy.**
   It is self-identifying and deterministic. The digest covers the canonical
   serialization of every ownership header field except the digest itself,
   concatenated with the LF-normalized body. Generator/protocol/host/artifact/
   assurance/version-range edits are therefore drift too. Every generated
   manifest entry stores that same digest. Authored-record `content_hash` values
   deliberately use exact stored bytes instead.
   Init writes it without creating `.roster/`; later synchronization can prove
   whether it is pristine from that clone-stable header. Authored registries and
   record files are never placed in a generated overwrite manifest.
6. **#342 builds generated-file machinery plus truthful minimal activation.**
   Claude receives create-only `.claude/CLAUDE.md`; if that authored path already
   exists, Roster leaves it untouched and uses an unscoped
   `.claude/rules/roster.md` fallback whose session-load behavior is pinned by a
   real host fixture. Codex receives create-only root `AGENTS.md` plus a
   `.agents/skills/roster/SKILL.md` fallback. If authored `AGENTS.md` already
   exists, Roster never edits it and reports Codex activation as
   `advisory-manual`, not equivalent auto-activation. Generated bootstrap files
   point only at `ROSTER.md`, `roster discover --json`, and `roster scaffold`.
   The full shared discover/context/record/Dreamer lifecycle remains #349;
   comprehensive drift consolidation remains #365.
7. **Legacy workspaces fail closed.**
   One workspace probe classifies `v2`, `legacy`, `mixed`, `unsafe`, or
   `none` from bounded regular-file markers and a conservative set of exact old
   managed signals. Legacy and mixed directories are preserved byte-for-byte
   and receive distinct migration/conflict guidance. There is no implicit
   overlay, `--force` conversion, directory inference, or permanent v1 shim;
   #363 owns migration.
8. **Registry traversal is declared; orphan inspection is narrow.**
   Discovery follows declared membership only. Structural validation may
   non-recursively enumerate only the fixed slot directories beneath a
   registered parent, with entry-count caps and component-wise confinement, to
   report unregistered collisions/orphans. Enumeration never mints identity.
9. **No discovery cache in #342.**
   The canonical hierarchy is read directly with bounded regular-file reads.
   The seeded fixture must meet the SPEC's 250 ms p95 target; a cache is added
   later only if measurement shows it is necessary.
10. **Mutations use a narrow workspace lock and commit-last publication.**
   This is filesystem safety, not a general queue, lease, journal, or operations
   runtime. A `mkdir`-exclusive lock records PID, process start time, and host;
   it is never broken automatically by elapsed time. `WORKSPACE_BUSY` names the
   exact lock path, owner host/PID/start time, and manual recovery rule after the
   operator confirms no live writer remains. Hosts do not blindly retry: they
   wait for the current local writer or present the recovery guidance.
11. **Generated metadata is deterministic and portable.**
    Install lazily creates `.roster/generated-manifest.json`, with no timestamp,
    machine path, or secret. It is intended to be committed so clone peers share
    the same expected host files; missing manifests can be reconstructed only
    from valid inline ownership/hash headers. `.roster/.gitignore` is generated
    create-only by the first operation that needs `.roster/`—scaffold, install,
    or update—before any state path is created, and ignores only
    `.roster/state/`; locks live at `.roster/state/locks/scaffold` and can never
    be committed accidentally.
    Authored files are never listed. Install creates the manifest; update repairs
    a missing one only when every claimed generated file has a valid inline
    ownership/hash header.
12. **Existing user-scope and Gemini installation remain quarantined.**
    Their unrelated removal is not pulled into this foundation ticket. Only
    Claude/Codex project installs participate in the v2 activation contract.

Current Claude Code documentation identifies `.claude/CLAUDE.md` as a project
instruction source and `.claude/rules/*.md` as project rules; an integration
fixture records the tested Claude version and verifies that the unscoped
fallback is session-loaded. Current Codex documentation confirms root
`AGENTS.md` is auto-loaded and `.agents/skills/` is discoverable. No managed
region or override is invented here: an existing authored root instruction file
always wins, and the install/doctor assurance state makes the resulting
asymmetry explicit until #349.

Generated metadata records the supported host version/range against which each
activation assurance fixture passed. A gated live-host release job writes the
checked-in attestation for that range; ordinary install never invokes a host
model. If the detected host version has no passing attestation—including no
binary/version detection—or the fixture disconfirms session loading, install
reports `advisory-manual` and never optimistically claims `auto-loaded`.

## Public v2 CLI delta

The block below defines new/changed v2 workspace behavior. Quarantined existing
install flags such as `--scope user`, `--tool gemini`, and `--all` remain
available only with the temporary behavior described in decision 12; their
omission here is not deletion.

```text
roster init [workspace-id] [--name <workspace-id>]
roster install --tool claude|codex --scope project [--json]

roster scaffold function <id> [--purpose <text>] [--json]
roster scaffold agent <id> --scope function:<function-id> [--purpose <text>] [--json]
roster scaffold plan <id> --scope agent:<function/agent> [--purpose <text>] [--json]
roster scaffold subagent <id> --scope agent:<function/agent> [--purpose <text>] [--json]
roster scaffold guideline <id>
  --scope function:<function>|agent:<function/agent>
  [--purpose <text>] [--json]
roster scaffold tool-use <id>
  --scope agent:<function/agent>|plan:<function/agent#plan>
  [--purpose <text>] [--json]
roster scaffold lesson <id>
  --scope agent:<function/agent>|plan:<function/agent#plan>
  [--purpose <text>] [--json]

roster discover [query]
  [--kind function|agent|plan|subagent|guideline|tool-use|lesson]
  [--scope function:<id>|agent:<function/agent>|plan:<function/agent#plan>]
  [--exact]
  [--full]
  [--json]

roster validate [target] [--json]
```

`validate` in this ticket is deliberately structural: registry versions,
common record envelopes, qualified identity, declared paths, ownership,
generated drift, bounded reads, and unsafe absolute/symlink/type findings.
Plan semantics/cycles belong to #344 and tool-use precedence/vendor-skill
semantics belong to #347.

JSON success responses use stable envelopes and lexical ordering. Discovery
uses `{ "ok": true, "records": [...], "diagnostics": [] }`; structural
validation uses `{ "ok": true, "checks": [...], "diagnostics": [] }`, where
each check has a stable name, severity, status, and details so later validators
can extend it. Discovery records contain:

```json
{
  "qualified_id": "gtm/social-manager",
  "kind": "agent",
  "path": "functions/gtm/agents/social-manager/agent.yaml",
  "purpose": "Manage evidence-based social discovery.",
  "scope": { "function": "gtm" },
  "schema_version": 2,
  "content_hash": "sha256:...",
  "references": { "plans": 1, "guidelines": 0 }
}
```

Record identity is the pair `(kind, qualified_id)`. Canonical qualified IDs are:

```text
function    gtm
agent       gtm/social-manager
plan        gtm/social-manager#opportunity-discovery
subagent    gtm/social-manager/subagents/researcher
guideline   gtm/guidelines/voice
guideline   gtm/social-manager/guidelines/voice
tool-use    gtm/social-manager/tools/social-search
lesson      gtm/social-manager/playbook/strong-hook
```

Plan-scoped tool-use/lesson records retain the owning agent path above and carry
the plan in structured scope metadata. One owning agent cannot register the same
local tool-use or lesson ID at both agent and plan scope because both map to the
same qualified ID/path; #347/#358 may add precedence-aware physical roots later.
Text discovery may return multiple pairs
and never silently selects one. `--exact` and every singular target resolver
require exactly one `(kind, qualified_id)` pair; an unqualified value matching
multiple pairs fails with `IDENTITY_AMBIGUOUS` and includes candidates. Exact
qualified queries are deterministic. Stable diagnostic codes include
`WORKSPACE_NOT_FOUND`, `LEGACY_WORKSPACE`, `MIXED_WORKSPACE`,
`UNSAFE_WORKSPACE_MARKER`, `IDENTITY_INVALID`,
`IDENTITY_AMBIGUOUS`, `PARENT_NOT_FOUND`, `DUPLICATE_IDENTITY`,
`PATH_ESCAPE`, `PATH_OVERLAP`, `RESERVED_PATH`, `SYMLINK_COMPONENT`, `NOT_REGULAR_FILE`,
`READ_LIMIT_EXCEEDED`, `SCHEMA_VERSION_UNSUPPORTED`, `UNKNOWN_FIELD`,
`IDENTITY_PATH_MISMATCH`, `GENERATED_FILE_EDITED`,
`ATOMIC_PUBLICATION_UNSUPPORTED`, and `WORKSPACE_BUSY`.

Every `--json` failure uses:

```json
{
  "ok": false,
  "code": "LEGACY_WORKSPACE",
  "message": "This is a Roster v1 workspace.",
  "remedy": "Preserve it and use the v2 migration command when #363 lands.",
  "details": {}
}
```

`RosterError` gains stable `code` and optional JSON-safe `details`. Success is
exit 0; argument, schema, collision, drift, unsafe-path, legacy/mixed, and
workspace-state failures use exit 1; explicit interactive cancellation remains
exit 2; missing/unsupported host tooling remains exit 3. Human output derives
from the same error object rather than a parallel prose-only path. This
intentionally changes today's `workspaceRequiredError` from cancellation (2) to
an actionable workspace-state failure (1).

## Authored registry and record model

Initial `roster.yaml`:

```yaml
schema_version: 2
workspace_id: my-roster
functions: {}
hosts: {}
```

The optional `brain` binding remains allowed but is never required for local
init, scaffold, discover, or structural validation.

Registered records:

```yaml
# functions/gtm/function.yaml
schema_version: 2
id: gtm
purpose: ""
agents: []
guidelines: []
```

```yaml
# functions/gtm/agents/social-manager/agent.yaml
schema_version: 2
id: social-manager
function: gtm
purpose: ""
plans: []
subagents: []
guidelines: []
default_guidelines: []
tool_uses: []
lessons: []
```

Plan, subagent, and tool-use YAML scaffold files expose a strict common
identity/draft envelope plus only the top-level fields already named by the
ratified SPEC. #342 does not claim those drafts are executable or implement a
plan/tool runtime. Guidelines and lessons use strict YAML frontmatter followed
by authored Markdown.

Canonical physical paths are:

```text
functions/<function>/function.yaml
functions/<function>/guidelines/<guideline>.md
functions/<function>/agents/<agent>/agent.yaml
functions/<function>/agents/<agent>/guidelines/<guideline>.md
functions/<function>/agents/<agent>/plans/<plan>.yaml
functions/<function>/agents/<agent>/subagents/<subagent>.yaml
functions/<function>/agents/<agent>/tools/<tool-use>.yaml
functions/<function>/agents/<agent>/playbook/<lesson>.md
```

Only a function root has a configurable path in `roster.yaml`. All descendant
paths are derived from the schema-v2 layout and explicit parent membership.
Components are lowercase kebab-case, length-bounded, and reject traversal,
controls, separators, case-only aliases, and platform-reserved names.
Function roots must be mutually non-overlapping—neither exact duplicates nor
ancestor/descendant prefixes—and disjoint from reserved roots including
`.roster`, `.claude`, `.codex`, `.agents`, `.git`, `roster.yaml`, and
`ROSTER.md`, root `AGENTS.md`, root `CLAUDE.md`, and every other path any current
Roster renderer may own. One exported `ROSTER_RESERVED_PATHS` registry is pinned
by tests against project install targets and legacy `project-context` renderers,
so adding a renderer cannot silently open a function-root collision.
Every configurable function-root path component follows the same lowercase-
kebab and reserved-name rules as IDs, preventing case-insensitive filesystem
aliases before confinement checks run.

## Implementation sequence

### 1. Establish one workspace filesystem boundary

- Extract generic bounded, `O_NOFOLLOW`, regular-file reads from the existing
  evidence reader without changing evidence behavior.
- Add component-wise no-symlink safe directory creation under a resolved
  workspace root; never import from the general-ops ledger that #362 removes.
- Add durable atomic replace and create-only publication. Create-only files are
  fully written and synced to a same-directory temporary regular file, then
  published with `link(2)` and the temporary name unlinked. `EEXIST` triggers an
  exact-byte idempotency/adopt-or-refuse comparison. If hard-link publication is
  unavailable, fail with `ATOMIC_PUBLICATION_UNSUPPORTED` and filesystem
  guidance rather than weaken the guarantee. Atomic `rename` is
  reserved for replacing a verified unedited generated file or locked parent
  registry after a source-hash recheck; it is never create-only publication.
  Sync both the completed file and containing directory after `link`/`rename`
  before reporting durable success.
- Add one lazy `ensureRosterStateRoot` primitive. Before it creates any state
  child, it safely creates/adopts `.roster/.gitignore` with the exact
  `.roster/state/` exclusion; scaffold, install, and update all use this entry
  point.
- Add a lazy `mkdir`-exclusive scaffold lock beneath `.roster/` with a bounded
  owner record (PID, process start, hostname) at
  `.roster/state/locks/scaffold`. Clean it after success/failure; never auto-break
  it based on age. Lock contention fails immediately with a stable diagnostic,
  the owner values in JSON-safe `details`, and exact manual-recovery path. The
  generated `.roster/.gitignore` makes the entire state subtree never-committed.
- Add confined, non-recursive, entry-count-capped slot enumeration for structural
  diagnostics. It rejects symlinked slot roots/entries and never traverses a
  discovered directory.
- Recheck confinement/type before and after each publication and keep injected
  filesystem seams for race/fault tests.

### 2. Implement schema-v2 identity, registry, records, and diagnostics

- Add strict bounded YAML/frontmatter parsing with byte, alias, node, scalar,
  and nesting caps appropriate to the common #342 envelopes.
- Preserve comments and ordering when adding membership to authored parent
  YAML; an explicit scaffold command authorizes the narrow membership update,
  not a wholesale normalization of unrelated authored bytes.
- Resolve qualified identities and canonical paths from declared parent
  membership only.
- Validate function-root overlap and reserved-path exclusions before resolving
  any descendant.
- Return compact deterministic records and stable diagnostics; `--full` includes
  bounded authored content only on explicit request.
- Define authored discovery-record `content_hash` as SHA-256 over exact stored
  bytes; authored CRLF changes are intentionally distinct bytes and therefore
  visible drift. Generated ownership/manifest hashes use the separate,
  explicitly canonical-header-plus-normalized-body domain from decision 5.

### 3. Replace init with the exact sparse contract

- Validate or derive the workspace ID.
- Preflight both targets through the shared workspace probe. Legacy signals
  include the existing v0.4 `projects/`, `<function>/projects/`, and
  `<function>/<agent>/projects/` markers already recognized by init; exact v1
  signals include `config/project.yaml`, `.roster/scaffold-manifest.json`, or a
  content-signature match across at least two known managed v1 leaf files
  such as `chief-of-staff/agent.md`, `dreamer/agent.md`, and
  `scripts/new-agent.sh`; one coincidentally named generic file is not enough.
  Both v1 and v2 signals are a `MIXED_WORKSPACE` refusal; unsafe marker types are
  a separate refusal.
- Create `ROSTER.md` first and publish `roster.yaml` last as the workspace
  sentinel; roll back only files created by the failed invocation.
- Init is deliberately lock-free so it can keep the exact two-file contract.
  Both publications are create-only and byte-deterministic for one workspace ID:
  concurrent identical init calls adopt the same bytes, while differing IDs or
  bytes collide without overwrite.
- Produce no `.roster`, `.git`, `.gitignore`, `.env*`, host file, function,
  guideline, log, placeholder, symlink, or `.gitkeep`.
- Exact repeat init is idempotent. Any authored/generated content mismatch fails
  without overwrite.
- `--name` and the positional ID normalize to one value; disagreement fails.
  Remove v1 init migration/force branches rather than silently converting a
  legacy tree.

### 4. Add deterministic on-demand scaffold

- Parse each kind and explicit owner/scope.
- Verify the parent is registered and structurally healthy.
- Under the workspace lock, preflight collisions, render the single requested
  record, create only necessary ancestors, and publish the child create-only.
- Atomically update the parent membership last after verifying its original
  hash. If parent publication fails, remove only the child and empty directories
  created by this operation.
- A crash-left byte-identical orphan may be adopted by an identical retry;
  differing bytes are an actionable collision.

### 5. Add flat discovery and core validation

- Traverse `roster.yaml` → registered `function.yaml` → registered `agent.yaml`
  and their declared slots. Never recursively scan unknown files. Structural
  orphan/collision reporting may inspect only fixed, registered-parent slot
  directories through the capped non-recursive primitive; entries remain
  non-canonical until an explicit matching scaffold adopts them.
- Verify registry path, embedded identity, scope, type, size, schema version,
  and content hash at every hop.
- Filter by kind, structured scope, qualified identity, or case-insensitive text
  query; sort by kind, qualified ID, then path.
- Report missing, malformed, duplicate, shadowed, orphan/collision, unsafe path,
  and generated-file drift without adopting or mutating anything.

### 6. Generate minimal Claude/Codex project activation safely

- Introduce a generated-artifact manifest with generator, protocol, schema,
  host, path, activation assurance, and exact content hashes. It lives at
  `.roster/generated-manifest.json`, is deterministic and intended for Git, and
  is created only by install/update—not init. Valid inline ownership/body-hash
  headers allow reconstruction if it is absent.
- For v2 project scope, render only the selected Claude/Codex bootstrap and the
  manifest; do not copy the legacy workspace agent/template forest.
- Claude installation reports `auto-loaded` only after the fixture confirms the
  selected `.claude/CLAUDE.md` or unscoped rule path on the pinned supported
  version. Codex reports `auto-loaded` when it safely creates generated root
  `AGENTS.md`; when authored `AGENTS.md` exists it adds only the project skill
  fallback and reports `advisory-manual`. `missing` is a failed install, not a
  success claim. Install and doctor expose these states in JSON.
- Update unedited generated files, refuse edited files, refuse symlink/type
  collisions, and never overwrite authored host instructions.
- Drift decisions are per-file. If a once-generated root `AGENTS.md` is later
  edited, update preserves it, reports `GENERATED_FILE_EDITED` for that path,
  refreshes other safe artifacts, installs/retains the Codex skill fallback,
  downgrades assurance to `advisory-manual`, and explains that the operator may
  either keep the authored file or restore the generated bytes. One conflict
  never blocks unrelated safe updates.
- After artifact publication, atomically add/update the selected host's enabled
  entry in authored `roster.yaml` under the same narrow mutation lock. This
  explicit install command authorizes only that registry field. Update reads the
  enabled host set; the generated manifest records actual assurance separately.
- Project install with an explicit host works even if no user-level host home
  exists. Unsupported v2 Gemini activation is explicit; existing user-scope
  install behavior remains unchanged.
- `roster update` on a v2 workspace synchronizes only enabled generated
  activation plus `ROSTER.md`; it never invokes the eager upgrader, hooks, or
  founder-skill side effects. `roster upgrade` refuses v2 and points to update.
- `roster skills sync|update` remains an explicit opt-in on a healthy v2
  workspace when its manifest exists, but is never called by v2 update. The
  shared workspace probe routes install, update, doctor, upgrade, and both skill
  commands consistently; legacy/mixed/unsafe states never enter v2 code.
- On a v2 probe, `roster doctor` runs only workspace classification, structural
  registry health, generated drift, per-host activation assurance, and the
  existing host-neutral safety/secret audits that remain valid for v2. Its v1
  skill/agent parity, shadow, scheduling, stale-fire, founder-skill, and expert
  route audits are reported `not-applicable` and excluded from `allOk`, so a
  sparse install cannot fail for intentionally absent legacy files. #366 owns
  the complete v2 activation and integrity doctor.
- V1 and mixed markers remain byte-preserved and receive #363 migration guidance.

### 7. Wire CLI, help, docs, and regression gates

- Add small argument/command modules instead of extending inline parsing.
- Help explicitly distinguishes install's `--scope project|user` from
  scaffold/discovery's `--scope kind:qualified-id`; the flag name is shared but
  command-local value namespaces cannot overlap.
- Update workspace-required errors and project-scope prompts from
  `config/project.yaml` to `roster.yaml`.
- Update README and smoke examples to the host-led sparse flow.
- Update the user-scope `inbox`, `tasks`, `roster-orchestrator`, and
  `chief-of-staff` skill guards to classify `roster.yaml` truthfully. In a v2
  workspace they must not invoke legacy config/scripts: inbox, tasks, and the
  orchestrator stop with explicit v2 replacement/roadmap guidance; Chief of
  Staff directs the host to deterministic `roster scaffold` commands. A v2
  workspace is never mislabeled "not a workspace" or sent into v1 creation.
- Keep legacy scaffold template bytes and legacy shell regression fixtures for
  the later migration/removal tickets, but ensure no v2 command reads or emits
  them. They intentionally remain in the package solely as frozen #363 migration
  input until #369 removes residual legacy product surfaces. Help and README
  name the temporary project-scope-v2 versus user-scope-legacy install split.
  Do not fix unrelated #372 in this ticket.

## Edge cases and security tests

- Invalid, reserved, Unicode/control, traversal, separator, and case-only IDs.
- Same-named agents and plans in separate functions; ambiguous bare queries.
- Missing parent, unregistered but present child, byte-identical orphan retry,
  differing orphan collision, and embedded ID/path mismatch.
- Absolute/custom path escape, duplicate/nested/overlapping function paths, and
  collision with generated/reserved roots.
- Symlink at every ancestor or leaf, including links that stay inside the
  workspace; FIFO, socket, device, directory, unreadable file, oversized file,
  and a file that grows during a bounded read.
- Concurrent different/same scaffold operations, stale parent hash, lock
  contention, SIGKILL-left lock recovery guidance, interrupted publication,
  hard-link/ENOSPC/write/rename failure, and rollback that never deletes
  pre-existing user bytes.
- First-scaffold SIGKILL proves `.roster/.gitignore` precedes lock state;
  ownership-header tampering changes the generated digest; missing/out-of-range
  host attestations remain `advisory-manual`.
- Generated activation missing, pristine, edited, wrong-type, mixed-version,
  stale-shadowed, or partially installed.
- Empty/exact/bare discovery queries, deterministic ordering, compact/full
  output, and stable JSON diagnostics.
- Missing Brain credentials do not affect init/scaffold/discover/validate.
- V2 update creates no authored optional tree; v1, mixed, and unsafe legacy bytes
  remain unchanged; v0.4 `projects/` shapes remain refused; founder-skill
  commands classify the same workspace state.
