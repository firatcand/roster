# Issue #346 implementation plan — bounded seeded task context

## Ticket

- GitHub: `firatcand/roster#346`
- Forge task: `P1-T05`
- Branch: `feat/346`
- Type: backend / public host-neutral context contract

## Outcome

Add `roster context <function>/<agent>[#plan] --query <task> ... --json` as
the thin, read-only boundary that gives Claude Code or Codex one deterministic
bundle for a task. Roster resolves authored workspace policy, validates and
returns the selected plan, retrieves only directly applicable context, accounts
for it under a caller-supplied token budget, and labels every source by trust.

Roster does not execute the plan. The host still interprets all steps, chooses
branches, delegates to subagents, invokes tools, carries outputs, waits for
human approval, and decides what happens next.

This ticket uses a narrow injected array of already materialized fake-Brain
candidates to prove selection, citations, trust separation, and budget behavior
without connecting the legacy Brain implementation or introducing network
access. The production CLI does not expose that seam through an argument, file,
environment variable, or stdin. The async authorized Postgres/S3 adapter in
#352 will materialize and freeze candidates before calling the same pure
assembler.

## Questions asked and answers applied

1. **Does one context response contain nested plan definitions, or fetch them
   later?** The owner chose **A** after a Claude Opus 5 xhigh second opinion:
   the root plan and the complete, deduplicated transitive closure of every
   statically referenced nested plan are mandatory content from one validated
   workspace snapshot. Optional Brain evidence, examples, and approved lessons
   remain budget-selected. The host alone decides which plans and branches to
   execute.
2. **Does an omitted `#plan` let Roster choose one?** No. Agent-only context is
   valid and returns no selected plan. Roster never infers a plan from list
   order, a step hint, or the request. The host must name a plan when it wants
   plan content.
3. **Which local records are mandatory?** Workspace identity/binding metadata,
   the selected function and agent definitions, agent `default_guidelines`,
   every guideline explicitly referenced by a selected/nested plan, the root
   plan, the nested-plan closure, and tool-use/skill-ref pairs named by actual
   `kind: tool` steps in that closure. The registry/function/agent/plan
   `tool_uses` arrays are ownership catalogs, not execution references.
   Membership alone never eagerly loads a guideline or tool definition.
4. **Which local records are optional?** Applicable approved lessons and every
   Brain evidence fragment are ranked under the remaining budget. Unreferenced
   guidelines and unreferenced tool definitions are not candidates. A plan
   Brain selector marked `required` is retrieval intent and the highest optional
   ranking priority; it never promotes evidence into the mandatory domain or
   turns an outage/no-match into a context failure.
5. **What does `step_hint` mean?** It is bounded `host-asserted` request data.
   It may contribute to optional relevance scoring and inclusion explanation,
   but cannot select or prune a step/plan, suppress policy, create a cursor, or
   appear as Roster execution state.
6. **What happens without `brain:`?** Return the complete local bundle with an
   empty evidence array and exactly one `BRAIN_NOT_BOUND` bundle diagnostic
   constructed explicitly with `severity: warning`; never route it through
   `workspaceFailure`, let it gate collection, or accept injected evidence.
   `roster context` exits successfully because Brain evidence is optional.
   The durable Brain-dependent-command contract retains fatal missing-binding
   semantics, but #346 adds no v2 Brain-only command path that consumes this
   registry binding.
7. **What if Option A's mandatory closure is larger than the 128,000-token
   command ceiling?** Do not return an impossible retry suggestion. Return the
   distinct closed `CONTEXT_MANDATORY_UNSERVABLE` error with safe per-section
   counts and the largest stable contributing IDs so the author can split or
   flatten the policy. Keep 128,000 because larger context is not useful to the
   intended host agents even though the filesystem collector safely accepts
   larger workspaces.
8. **Which optional source wins scarce budget?** Human-approved lessons rank
   ahead of untrusted Brain extracts. `brain_selectors.required` ranks a match
   first only inside the Brain tier and remains nonfatal retrieval intent.

No unresolved product fork remains.

## Public CLI contract

Add a command-local parser in `src/lib/context-args.ts`:

```text
roster context <function>/<agent>[#plan]
  --query <task>
  [--step <host-supplied-hint>]
  [--budget <tokens>]
  [--explain]
  --json
```

Rules:

- Target parsing is exact lowercase identity parsing. It accepts no path,
  fuzzy/local match, glob, environment expansion, `--cwd`, or alternate scope.
  Reuse `parseAgentQualifiedId`, `parsePlanQualifiedId`, and `isRecordId` from
  `workspace-layout.ts`; do not hand-roll a second grammar. Catch their typed
  `IDENTITY_INVALID` failures inside the command-local parser and return the
  public `INVALID_ARGS` envelope for malformed target syntax. This is a
  deliberate command-syntax boundary: unlike discovery of an already parsed
  identity, a malformed positional target is invalid argv for host adapters.
- `--query` and `--json` are required. Query and step values are non-empty,
  UTF-8 bounded, control-safe, and scanned for secret material before echo.
- The provisional default budget is 8,000 tokens. Accept only canonical
  base-10 safe integers in
  `MIN_CONTEXT_BUDGET_TOKENS..MAX_CONTEXT_BUDGET_TOKENS`, where the minimum is
  `BUDGET_BLOCK_RESERVE_TOKENS + 1` and the maximum is 128,000; reject leading
  zeroes, signs, fractions, exponents, unsafe integers, duplicate flags,
  missing values, unknown flags, and surplus positionals. The representative
  context benchmark must prove its mandatory domain uses at most 50% of the
  default. If not, raise the default to the next 1,000-token boundary at or
  above twice the measured mandatory total and update the parser/spec/fixtures;
  never shrink the representative fixture. That sizing rule uses the fixed
  representative task query/hint, not the maximum legal 16 KiB/4 KiB request;
  maximum-length requests remain valid but are expected to require an explicit
  larger `--budget` through the exact overflow retry contract.
- `--explain` emits bounded safe detail only in
  `provenance[].explanation`. That detail is fully budgeted, so equal inputs
  with different explain values may change the mandatory minimum/overflow
  verdict and admit different optional fragments. Mandatory content, order,
  IDs, hashes, reason codes, and response keys remain identical; mandatory byte
  counts need not.
- JSON mode writes exactly one JSON document to stdout and no parallel
  diagnostics to stderr. Argument and resolver failures use the existing stable
  JSON failure envelope and nonzero exit semantics. Success never adds `ok` to
  the context response.
- Every context `INVALID_ARGS` message/remedy/detail is constructed from the
  flag name, a closed reason, and bounded numeric facts such as observed byte
  length/limit/offset. It never copies a raw query, step, positional target, or
  unknown argument. Down-mapping `IDENTITY_INVALID` drops its original
  `details.value`/`details.label`. The command may reuse `commandParseError` only
  after producing this sanitized closed message.

Dispatch `context` locally before the existing global help/version scan and
handle a sole context `--help`/`-h` request in that path by calling the existing
global `printHelp(version)`—do not add a bespoke subcommand help renderer. Leave
the global scan and all other subcommand behavior byte-identical. Thus
`--query -v --json` and
`--step --help --json` reach the context parser and produce a nonzero stable
`INVALID_ARGS` JSON envelope instead of bare help or a version string, without
changing `brain`, `schedule`, `run`, `ops`, install, or doctor help behavior.

Wire the parser and a small `src/commands/context.ts` serializer through
`src/bin/roster.ts`, including help text and the `Subcommand` allowlist. The
command passes no fake candidates; it only supplies the workspace root and
validated request to the library resolver.

## Exact response shape

The response has exactly these top-level keys in this order:

```json
{
  "schema_version": 2,
  "workspace": {},
  "target": {},
  "request": {},
  "agent": {},
  "plan": {},
  "guidelines": [],
  "lessons": [],
  "brain_evidence": [],
  "tool_uses": [],
  "skill_refs": [],
  "provenance": [],
  "budget": {},
  "diagnostics": []
}
```

The DTO contains only JSON-safe primitives, arrays, and plain objects. It never
contains `undefined`, non-finite numbers, `BigInt`, classes, absolute workspace
paths, or platform/user/host/time/random values.

- `workspace` contains schema version, stable workspace ID, source hash, and
  the non-secret Brain binding name or `null`. It does not echo the complete
  registry or unrelated function membership.
- `target` contains exact function, agent, and nullable plan identities.
- `request` contains the bounded query, nullable host step hint, budget, and
  explain flag, with query/hint classified as `host-asserted` in provenance.
- `agent` contains separate function and agent policy fragments.
- `plan` is `{ root_id, definitions }`; `root_id` is nullable and definitions
  contain root first followed by the code-point-sorted deduplicated closure.
  Each definition preserves its authored step/array order.
- `guidelines`, `lessons`, `brain_evidence`, and `tool_uses` remain separate
  arrays. Equal text across arrays is never coalesced or promoted.
- `skill_refs` contains canonical ref and reviewed locator/provenance only. It
  never contains vendor skill bytes or claims a host-native skill is installed.
- `provenance` has one bounded entry per included fragment, using stable IDs
  rather than copied untrusted prose.
- `budget` uses the single normative field list defined in the deterministic
  budget section below.
- `diagnostics` contains only sanitized typed diagnostics. No diagnostic embeds
  raw evidence, source snippets, credentials, or provider exception messages.

Success deliberately omits `ok`, while a fatal envelope carries `ok: false`;
#349 host adapters must branch on process status/envelope shape rather than
expecting the `discover`/`validate` result convention.

Every fragment carries:

- stable `fragment_id`, kind, and declared scope;
- `source_content_hash` for exact authored bytes where a local source exists;
- `fragment_hash` for the exact canonical JSON value emitted as content;
- trust class and closed inclusion-reason code;
- required/optional status; and
- canonical `content_bytes`/`content_tokens` for the emitted `content` value.

Local structured YAML fragments emit the validated closed parsed projection,
not raw YAML. Guideline and lesson `content` is the closed parsed
`{ id, kind, purpose, scope, body }` projection matching
`MarkdownDefinition`; `body` is the normalized
Markdown body after frontmatter, while `source_content_hash` still hashes every
exact authored source byte. Thus `fragment_hash` always covers the canonical
host-facing value and never masquerades as the raw-source hash.

`brain_evidence[]` has its own public DTO and is not an alias, extension, or
spread of the internal seed type. In addition to the standard fragment
envelope, it carries `privacy`, exact candidate `scope`, a closed retrieval
reason, untrusted `content`, and:

```ts
type ContextBrainCitation = {
  logical_source_id: string;
  source_version_id: string;
  object_id: string | null;
  extractor_id: string | null;
  extractor_version: string | null;
  locator: string;
  content_hash: string;
};
```

The citation envelope is additive-only for response `schema_version: 2`.
Every seed field is validated and explicitly projected; unknown seed fields
never flow into output.

Effective tool uses additionally preserve the existing `semantic_hash` and
ordered contributors. Their composite fragment has
`source_content_hash: null`; exact source identities are the ordered
`contributors[].content_hash` values plus `semantic_hash`. The raw-source hash
is never represented as the hash of parsed/normalized content.

## Trust and inclusion classes

Define the full forward-compatible SPEC trust union now—`authored-policy`,
`approved-lesson`, `vendor-instruction`, `brain-structured`,
`brain-extract-untrusted`, `tool-output-untrusted`, `host-asserted`,
`legacy-unverified`, and `diagnostic`—rather than widening a public closed union
in #352. This seeded phase may emit only the following subset:

| Section | Trust | Normal role |
|---|---|---|
| function, agent, plans, guidelines | `authored-policy` | mandatory when selected/referenced |
| lessons | `approved-lesson` | optional, applicable scope only |
| fake Brain evidence | `brain-extract-untrusted` | always optional; required intent ranks first inside the Brain tier |
| effective company tool guidance | `authored-policy` | mandatory only when named by a selected-closure tool step |
| canonical skill locator | `vendor-instruction` | coherent with its referenced tool use |
| query and step hint provenance | `host-asserted` | request metadata only |
| diagnostics | `diagnostic` | never policy/evidence |

Injected candidates cannot supply their trust, required/optional flag,
inclusion reason, score-to-budget decision, policy kind, or output section.
Roster clamps all seeded evidence to `brain-extract-untrusted`; it never assigns
the authoritative `brain-structured` class in this seeded phase. Brain and tool
text cannot become an instruction, plan, guideline, lesson, tool-use rule, or
vendor locator.

## One-generation workspace source

The existing complete snapshot is the sole local authority. Do not build a
context from filtered discovery records or reconstruct `snapshot.records`.

Extend the registry-owned collector so one function returns a recursively
frozen `PreparedContextSource { snapshot, registry_metadata,
registry_source_hash, counts }`, captured from the same `WorkspaceReadSession`.
The assembler never accepts a loose snapshot/metadata pair. The source contains:

- the branded, recursively frozen full-content record array;
- a cloned/frozen projection of parsed `roster.yaml` metadata needed by context;
- the exact `roster.yaml` source hash; and
- aggregate record/byte counts.

The context path uses a registry-owned synchronous higher-order read capability
so one opt-in `WorkspaceReadSession` stays alive through snapshot collection,
assembly, and final verification:
`withContextReadCapability<T>(root, fn: (cap) => T): T`. #352 may add an async
overload when it introduces a real remote await; #346 does not speculate that
contract. The capability exposes only frozen source data, a selected-ref vendor
projection method, and a terminal verifier; only `workspace-context.ts` may
import it. Vendor/founder/project provenance walks use their existing confined
readers outside the session and are protected by the explicitly repeated
restricted derivation plus terminal comparison; the plan does not claim those
reads share the session. Existing pre-parse scanning remains only on already-
covered tool/vendor/founder surfaces.

The wrapper refuses to return successfully unless its terminal verifier is
called exactly once. Context-mode IO pins registry/local-record leaves genuinely
read through its session. Vendor manifest/lock/map and project-skill walks stay
outside that session and receive the separate content-hash guarantee below; do
not add ambient recording state or claim their inode identity is observed.

The internal snapshot mint remains importable only by
`workspace-registry.ts`; add/extend the static boundary guard. Context receives
the prepared source only from a registry-owned exported collector. It never
re-reads `roster.yaml`, calls fuzzy discovery, uses `resolveRegisteredRecord`,
or mints/filters/copies a substitute snapshot.

Registry exports `assertPreparedContextSource(value)` as the only brand
validator; it validates the private-symbol brand/frozen structure without
minting or exposing the symbol. Pure assembler tests obtain a real prepared
source through `withContextReadCapability` over a fixture and never synthesize
or cast one. The sole-importer guard is scoped to production `src` files:
`src/lib/workspace-context.ts` is the only production importer, while
`test/workspace-context.test.ts` is the one explicit test importer.

The context collector opts into aggregate bounds while collecting, without
changing ordinary discovery/validation behavior: at most 8,192 registered
records, 64 MiB of exact record content, and 4,096 entries in any registry
membership array. Existing per-file YAML/Markdown limits remain. These limits
sit above the existing 3,111-record stress fixture. Exceeding a bound fails
before any response/digest/provenance is published; regression tests prove the
shared discover/validate fixture remains accepted.

After assembly and vendor-map selection, re-read and compare the registry and
every emitted local workspace record by confined path, exact source hash, and
file identity through a context-only read-session verification mode. For these
session-owned local records, removal, byte change, namespace change, or
hash-equal inode replacement produces retryable `WRITE_CONFLICT`; this
deliberately chooses snapshot identity over accepting a concurrent identical
rewrite. No write lock or mutation is used. The ordinary `WorkspaceReadSession`
fast path is unchanged. Its opt-in context mode remembers local leaf
identities/hashes so read A → replace A → read B → verify cannot succeed.

Vendor/founder/project-skill integrity is explicitly content-hash-based, not
inode-based. When skill refs are selected, derive the same restricted
`buildVendorSkillMap` input twice and require byte-identical expected output;
terminally re-read the stored generated map and require unchanged exact bytes,
canonical parse, and valid self-hash. A byte-identical replacement of a vendor
artifact is accepted by design because the emitted locator contains only path,
content hash, and reviewed provenance. Stronger inode/listing pinning would
require an injected reader contract in adapter-map and is outside #346.

The exact guarantee covers every byte emitted in the bundle and every record
whose bytes contributed to an emitted value: selected function/agent,
plans/guidelines/lessons, and every `ToolUseContributor.path` folded into an
effective tool use, plus registry and vendor/founder/project provenance used for
selected locators. The former use session identity/hash verification; the
vendor/founder/project inputs use the content-hash guarantee above. Other
non-contributing registered records participate only as identity catalogs and
are pinned by their containing directory identity; their bodies cannot affect
selected content. Tests name this boundary.

Re-probe the workspace classification at the terminal verification boundary and
bind it to the same root identity. A v2→legacy/mixed/unsafe namespace change
during the initial probe/read window fails rather than yielding a stale v2
bundle.

The command is observationally read-only: no `.roster` lock/state write,
scaffold/update/sync, cache lookup, network, process execution, provider call,
Brain write, evidence write, or generated-file repair.

## Plan and policy resolution

Add `resolveValidatedPlanClosure(snapshot, rootId)` beside
`resolveValidatedPlan` in `src/lib/workspace-plan.ts`; accepting the branded
snapshot directly removes a redundant records parameter that could be paired
incorrectly.

1. Call exactly
   `validateStructuredPlans(snapshot.records, [rootId], snapshot)` once. Passing
   the snapshot as the third argument is mandatory for tool-step validation and
   activates the existing record-array identity check.
2. Reject every schema/reference/tool/cycle diagnostic in that selected
   closure before emitting anything. Envelope/frontmatter-unparseable or
   identity-mismatched registered records of any kind fail during complete
   snapshot collection. Structurally invalid plan bodies (unknown/forbidden
   field, bad step kind, duplicate step ID, incomplete draft) fail only when
   they are in the selected transitive closure; an unrelated structurally
   invalid plan does not block targeted context. Every broken transitive plan
   fails closed.
3. Return the parsed root plus the complete selected closure once. Root is
   first; remaining unordered definitions use a locale-independent Unicode
   code-point comparator. Authored steps and ordered fields retain source order.
4. Select a fatal diagnostic with a context-local Unicode code-point tuple
   `(code, path, field_path, message)`. Forward the selected shared diagnostic
   payload rather than duplicating/parameterizing the existing SCC/cycle
   implementation; successful bundle determinism does not require rewriting a
   fatal cycle explanation. Existing `resolveValidatedPlan` behavior/tests
   remain unmodified; only the new context closure wrapper chooses the fatal
   diagnostic deterministically from the produced set.
5. Do not automatically load cross-agent definitions, subagent definitions, or
   nested-agent policy. A nested/cross-agent plan body is present because of
   Option A; the host requests that agent's own context when it delegates. For
   a `kind: subagent` step, the host retrieves the registered definition via
   exact `roster discover --kind subagent --exact
   <function>/<agent>/subagents/<id> --full --json`; #349 must teach that
   recovery path rather than expanding this bundle.

Resolve target policy only from the same snapshot:

- exact selected function and agent records;
- each unambiguous agent `default_guidelines` reference;
- every qualified guideline named by root/nested plans, including a
  cross-agent nested plan's explicitly named guideline as the narrow exception
  to the no-implicit-nested-agent-policy rule; and
- registered lessons owned by the selected agent whose optional plan scope is
  absent or names any plan in the emitted closure.

Function/agent guideline membership is a catalog, not an eager include rule.
Lesson applicability does not make a lesson mandatory. In this phase a
registered lesson file is, by definition, approved and non-retired; retirement
is removal from the registry/file set, and #346 adds no status field to the
closed Markdown schema. Optional ranking prefers root-plan scope, then nested-
closure scope, then unscoped lessons; sibling non-closure lessons are excluded.

## Tool-use and vendor-skill selection

Build the stable set of explicitly referenced local tool IDs exclusively from
`kind: tool` steps across every plan definition in the closure. Ownership
catalogs named `tool_uses` never select context. For each `(plan ancestry, local
tool ID)` pair, call `resolveToolUse` with the same branded snapshot, using the
step's owning plan ancestry. Deduplicate only identical effective semantic
identities while preserving all applicable plan/step reasons. Tool guidance and
its canonical skill-ref entry form a coherent mandatory pair; neither is
silently truncated alone.

Add a targeted registry/vendor helper that:

1. parses and self-hash-validates the canonical generated map;
2. verifies every selected canonical ref has an entry;
3. calls the existing `buildVendorSkillMap` with `skillRefs` restricted to the
   selected refs and `skillRefPaths` restricted to selected contributors,
   reusing the canonical locator derivation rather than copying it;
4. compares each selected `hosts` object exactly and requires selected
   contributor paths to be a subset of the stored `authored_paths`; and
5. returns a projection containing only selected refs and paths.

`workspace-registry.ts` owns the target helper and calls the existing adapter-
map API. Run the same restricted `buildVendorSkillMap` input twice: once during
assembly and once at terminal verification, requiring byte-identical expected
output plus unchanged stored-map bytes. This re-walk covers the manifest,
lockfile, and complete selected project-skill trees without changing or
duplicating `adapter-map.ts`. Benchmark the second walk against the existing
4,096-entry / 4 MiB per-host tree limits and the 500 ms representative target.

Unrelated valid/draft tool entries do not block the target and are never
emitted; an envelope/frontmatter-unparseable registered record still fails the
complete snapshot.
Missing, drifted, malformed, mutable-assurance-misrepresented, or
target-incomplete entries fail closed. `host-native` remains
`assurance: host-resolved`; project-relative locators retain confined path,
reviewed content hash, source, revision, immutability flag, and
`assurance: verified`. Locator metadata is not a provider route and Roster does
not read vendor skill content into the bundle.

When at least one skill ref is selected, global manifest/lock disagreement and
a malformed/self-hash-invalid generated map remain fatal even when their
offending extra entry is unselected; those files are then shared provenance
authorities. When the request selects no skill refs, do not read or validate
founder manifest/lock/map artifacts at all. Valid extra stored-map entries for
unselected refs are inert and omitted. Pin all three cases in tests.

## Seeded Brain seam

Keep the assembler pure and synchronous. Its caller passes a recursively frozen
candidate array plus a closed source-status value; there is no reader/client
inside the assembler:

```ts
type SeedBrainCandidate = {
  candidate_id: string;
  binding: string;
  selector: string;
  scope: { workspace: string; function?: string; agent?: string; plan?: string };
  content: string;
  current: boolean;
  tombstoned: boolean;
  privacy: 'public' | 'internal' | 'secret';
  retrieval_rank: number;
  citation: {
    logical_source_id: string;
    source_version_id: string;
    object_id: string | null;
    extractor_id: string | null;
    extractor_version: string | null;
    locator: string;
    content_hash: string;
  };
};
```

```ts
type ContextEvidenceInput = {
  status: 'seeded' | 'unavailable';
  candidates: readonly SeedBrainCandidate[];
};
```

`status: unavailable` requires an empty candidate array; any other combination
is `CONTEXT_EVIDENCE_INVALID`. A bound workspace with `status: seeded` evaluates
every bounded input candidate exactly once. An unbound workspace ignores the
entire injected seam before this invariant because no candidate is authorized.

The closed selector catalog is the code-point-deduplicated union of
`brain_selectors` keys from every plan in the closure and `brain.read` entries
from each selected effective tool use. Each entry carries its origin
`plan-selector | tool-use-intent`; only a plan selector can carry
`required: true` retrieval intent. Tool-use-only selectors can match evidence
but never receive required-intent ranking.

Bound that deduplicated catalog to `MAX_CONTEXT_SELECTORS = 4096`; overflow is
closed `READ_LIMIT_EXCEEDED` with `bound: context-selector-catalog` before
candidate evaluation. `budget.required_selectors_unmatched` counts distinct
unmatched required selectors and is therefore also at most four digits.

The resolver receives a cloned/frozen request containing binding, target,
query, nullable hint, and that catalog alongside this input. It:

- rejects candidates for another binding/workspace/scope;
- excludes secret privacy, detected secret material, stale, tombstoned,
  malformed, uncited, duplicate, or unrequested candidates before ranking;
- never treats selector strings as SQL, filesystem paths, commands, or grants;
- intersects candidates with the authored selector catalog and selected target;
- uses closed exclusion reason codes and never copies candidate prose into an
  inclusion reason/diagnostic;
- ranks matches for selectors marked `required` ahead of other Brain evidence
  while keeping approved lessons in the higher optional trust tier and keeping
  all Brain matches optional; and
- emits a bounded typed diagnostic/exclusion count when a required-intent
  selector has no eligible candidate, without corrupting local mandatory
  material.

`retrieval_rank` must be a safe integer in `0..1000000`; non-finite, fractional,
negative, or oversized values receive a closed invalid-candidate exclusion
before sorting. Candidate identity is bounded and unique after duplicate
rejection, and code-point candidate ID is the final tie-break, making the tuple
total even when remote ranks repeat.

Term overlap is exact and locale-independent: NFC-normalize, call
`String.prototype.toLowerCase()` (never `toLocaleLowerCase`), split on
`/[^\p{L}\p{N}]+/u`, drop empty terms, retain at most 64 distinct query/hint
terms and 512 distinct candidate terms in code-point order, and score the
integer count of query/hint terms present in the candidate set. Pin a Turkish
I/dotless-I locale canary.

Tuple comparison is descending for trust/required/exact/overlap/scope,
ascending for retrieval rank and final identity. Lessons use zero sentinels for
Brain-only required/exact/retrieval fields; their higher trust tier decides
before those fields. Root-scoped lessons outrank nested-scoped, which outrank
unscoped lessons inside the lesson tier.

Bound host query to `MAX_CONTEXT_QUERY_BYTES = 16384`, step hint to
`MAX_CONTEXT_STEP_BYTES = 4096`, each candidate content field to 256 KiB,
selector/locator strings to 4 KiB, grammar-constrained candidate/binding/scope/
source/version/object/extractor/hash IDs to 256 bytes each, and the complete
encoded evidence input to `MAX_CONTEXT_EVIDENCE_BYTES = 16 MiB`. Violations are
closed `CONTEXT_EVIDENCE_INVALID` before scanning/ranking and never echo the
value.

If `brain:` is absent, injected candidates are ignored and nonfatal
`BRAIN_NOT_BOUND` is reported exactly once with explicit `severity: warning`;
it is a bundle diagnostic, is never thrown, and never affects exit status. If
source status is `unavailable`, emit a closed
`CONTEXT_EVIDENCE_UNAVAILABLE` bundle diagnostic; never echo a database URL,
credential, stack, or provider text. In #352 the async adapter catches its own
errors, materializes/freezes candidates or this status, then invokes the same
pure resolver. The separate `budget.required_selectors_unmatched` value is `0`
when Brain is unbound; `BRAIN_NOT_BOUND` is the sole missing-binding signal. In
#346, `unavailable` is reachable only through direct
assembler tests because the production CLI supplies no Brain adapter.

The CLI command never imports a legacy Brain client or exposes candidate
injection. Static tests forbid imports from legacy Brain/search, persistence,
AWS/Postgres/OpenAI clients, network/process modules, and provider routers.

## Deterministic budget algorithm

Implement a read-only `resolveWorkspaceContext` orchestrator and a filesystem-
free `assembleWorkspaceContext(source, request, evidenceInput)` core in
`src/lib/workspace-context.ts`:

1. Parse exact target and collect the one-generation source.
2. Resolve function, agent, optional root, complete nested closure, required
   guidelines, explicitly referenced tool/skill pairs, applicable lessons, and
   eligible Brain candidates.
3. Apply the existing shared detector only on the local/vendor surfaces that
   validation already scans. On raw query/step values and every Brain candidate
   string, apply both that shared detector and the context-local detector before
   echo or ranking, merging findings deterministically. Do not introduce a
   stricter context-only scan of authored workspace prose.
4. Create all mandatory local fragments and their provenance first. Brain
   matches never enter this set.
5. Calculate the mandatory accounted domain and add the constant budget-block
   reserve. If that minimum exceeds `MAX_CONTEXT_BUDGET_TOKENS`, throw
   `CONTEXT_MANDATORY_UNSERVABLE` with the maximum, exact required byte/token
   counts, per-section counts, and at most 16 largest contributing stable record
   IDs/counts, ordered by bytes descending then code-point ID; the remedy tells
   the author to split/reduce those definitions.
   Otherwise, when it exceeds this request's limit, throw
   `CONTEXT_BUDGET_REQUIRED_OVERFLOW` with `limit`, the exact reachable minimum
   retry `required_tokens`/`required_bytes` including reserve, and per-section
   required counts only. Either error emits no fragments, hashes, provenance,
   source prose, or partial bundle.
6. Rank optional lessons and Brain evidence by a fixed integer relevance tuple:
   trust tier (`approved-lesson` before `brain-extract-untrusted`), Brain-only
   required intent, exact selector match, normalized query/hint term overlap,
   declared retrieval rank, scope specificity, then code-point identity. Never
   use time, randomness, locale collation, platform paths, or host identity.
7. Pre-serialize each optional content fragment and its provenance once;
   pre-serialize each later diagnostic example once without provenance.
   Maintain one exact accounted-domain byte counter. Content marginal cost is
   the canonical item bytes plus the required one-byte array separators for its
   destination array and `provenance`; diagnostic marginal cost is its item plus
   the `diagnostics` separator. Admit when
   `ceil((domain_bytes + marginal_bytes) / 4) + reserve_tokens <= limit`, then
   add that marginal exactly. This is O(1) accounting per candidate after its
   one serialization, rather than serializing the whole response per candidate.
   A Brain evidence skip increments candidate exclusion `budget-exhausted`; a
   lesson skip increments `lessons_budget_exhausted`; an optional diagnostic
   skip increments `candidate_diagnostics_omitted`. A skip never stops later,
   smaller candidates from being considered. Never truncate a fragment.
8. Verify rather than reconcile: recompute and assert every reported domain
   total, assert the serialized response is within the limit, calculate hashes,
   scan the eligible egress surfaces, perform final file/map revalidation,
   assert forbidden Roster-owned keys are absent, freeze, and return. A mismatch
   fails closed; no derived field is adjusted after serialization.

The estimator is fixed and named, initially
`utf8-bytes-ceil-div-4/context-canonical-json-v1`: canonical context JSON uses
the declared schema field order for closed DTO objects, Unicode code-point key
ordering for unordered maps, preserves array order, encodes UTF-8, and
estimates `ceil(bytes / 4)` tokens. A fragment's own accounting reports the
exact canonical bytes/tokens of its `content` value, avoiding self-reference;
all wrapper/provenance overhead is covered by bundle accounting.

The accounted domain is the canonical serialization of every response section
except `budget`: `schema_version`, `workspace`, `target`, `request`, `agent`,
`plan`, `guidelines`, `lessons`, `brain_evidence`, `tool_uses`, `skill_refs`,
`provenance`, and `diagnostics`, including every explanation string. `budget`
is covered separately by compile-time `BUDGET_BLOCK_RESERVE_BYTES` and
`BUDGET_BLOCK_RESERVE_TOKENS`, equal to the canonical size of the widest legal
complete budget response member: fixed estimator/version, six-digit limit,
eight-digit byte/token totals, every closed candidate-exclusion counter, and
the three separate bounded scalars at four digits under the context membership/
evidence bounds. A test serializes that maximum member and pins both constants.

Bound `ContextEvidenceInput.candidates` to
`MAX_CONTEXT_EVIDENCE_CANDIDATES = 4096`; a larger array fails with closed
`CONTEXT_EVIDENCE_INVALID` before ranking. Together with the 4,096-entry
membership bound on applicable local lessons, the optional pool is at most
8,192 entries and its exclusion counts remain four digits. Define
`effective_limit = limit - BUDGET_BLOCK_RESERVE_TOKENS`.

The mandatory domain is the accounted response with optional lesson/Brain
arrays and their provenance empty: schema/workspace/target/request scaffolding,
function/agent/plan, mandatory guidelines/tool uses/skill refs, mandatory
provenance, empty optional sections, and only source/request diagnostics.
Mandatory diagnostics are capped at `MAX_CONTEXT_MANDATORY_DIAGNOSTICS = 8`;
Brain state produces at most one of nonfatal `BRAIN_NOT_BOUND`,
`CONTEXT_EVIDENCE_UNAVAILABLE`, or aggregate
`CONTEXT_REQUIRED_EVIDENCE_MISSING`. Per-candidate
`CONTEXT_EVIDENCE_EXCLUDED` diagnostics never enter the mandatory domain. They
are code-point sorted and considered only after all lesson/evidence fragments,
using the same exact marginal accounting against the `diagnostics` array, with
at most `MAX_CONTEXT_OPTIONAL_DIAGNOSTICS = 64` admitted. Thus noisy optional
input cannot turn a servable mandatory bundle into overflow. Aggregate truth
stays in the fixed budget counters even when zero example diagnostics fit.
The mandatory diagnostic set is provably at most eight by construction; a
larger derived set is an internal invariant violation and becomes sanitized
`CONTEXT_RESOLUTION_FAILED`, never silent truncation.

The optional domain is the exact marginal accounted cost of admitted
lessons/Brain evidence, their provenance, and admitted per-candidate diagnostic
examples. Diagnostics remain a pure function of request/source/evidence
eligibility; only their budget admission is a fit decision, reported by the
fixed `candidate_diagnostics_omitted` counter.

`budget` has exactly this declared-order field list:
`estimator`, `limit_tokens`, `mandatory_bytes`, `mandatory_tokens`,
`optional_bytes`, `optional_tokens`, `reserve_bytes`, `reserve_tokens`,
`total_bytes`, `total_tokens`, `remaining_tokens`, candidate `exclusions`,
`lessons_budget_exhausted`, `required_selectors_unmatched`, and
`candidate_diagnostics_omitted`. It reports non-self-referential values with
`total_tokens = mandatory_tokens + optional_tokens + reserve_tokens` and
`remaining_tokens = limit_tokens - total_tokens`.
Round the accounted domain only once:
`final_domain_tokens = ceil(final_domain_bytes / 4)`,
`mandatory_tokens = ceil(mandatory_bytes / 4)`, and
`optional_tokens = final_domain_tokens - mandatory_tokens`; optional bytes are
`final_domain_bytes - mandatory_bytes`. Therefore
`total_tokens = final_domain_tokens + reserve_tokens` and
`total_bytes = final_domain_bytes + reserve_bytes` even when both byte domains
have nonzero remainders. Never sum independently rounded fragment or domain
estimates. The reserve covers the complete canonical budget response member,
including its key and surrounding JSON punctuation, at its widest legal value.
The actual member never exceeds that reserve, so actual serialized tokens are
at most reported total and reported total is at most the caller limit.

When the mandatory minimum is within the accepted ceiling, exact fit succeeds
at `limit = mandatory_tokens + reserve_tokens`; one token below returns the
reachable overflow. A larger mandatory minimum is unservable, not a retry hint.
Equivalent source
versions, target, query, hint, budget, explain flag, and candidate set produce
byte-identical semantic JSON regardless of Claude/Codex caller, absolute clone
root, input candidate permutation, locale, or repeat invocation.

`workspace-context.ts` owns one Unicode code-point comparator implemented over
iterated scalar values/`codePointAt`; do not reuse the registry's punctuation-
weighted lexical helper, adapter-map's UTF-16 comparator, bare `.sort()`, or
`localeCompare`. Duplicate candidate IDs are rejected as complete groups—never
"keep first"—so input permutation cannot choose an emitted value.

- `CONTEXT_RESOLUTION_FAILED` for sanitized unexpected internal failures

Use existing `WRITE_CONFLICT`, `SKILL_REF_DRIFTED`, and schema/reference codes
for integrity failures rather than inventing a less precise context wrapper.

serializer. `sanitizeContextFailure` preserves a recognized closed code but

recorded for a validate-first follow-up rather than widened into #346.

Leave the shared authored detector's behavior, detector union, and findings
byte-identical; the only source delta there is exporting its existing private
`hasCredentialShape` predicate for reuse. Keep context acceptance equal to

aggregate bounds and selected-closure contract. Context makes no claim about
unselected records that validate checks globally. A workspace accepted by
validate must never be rejected by context solely because of its selected
function, agent, plan, guideline, lesson, or `roster.yaml` prose. Fatal
`SECRET_MATERIAL_FORBIDDEN` for local/config/vendor bytes comes only from the

generated vendor/project-skill provenance, and founder-skill manifest/lock.
Context adds no stronger authored-prose pattern in this ticket.

On surfaces validate never sees and Roster never treats as policy—host
`--query`/`--step` values and every Brain candidate content, selector, ID,

`(field, byte_offset, detector_id, match_length)`. The local scanner's closed

(`REPLACE_ME*`, `<...>`, `${...}`, `xxx*`, `changeme`, `example`, or empty).

ticket; context then inherits it from the shared detector.

Define the complete emitted exclusion-key set now because its fixed shape is
part of public accounting: `stale`, `tombstoned`, `unauthorized`,
`privacy-incompatible`, `duplicate`, `low-trust`, `secret-material`,
`invalid-rank`, `unrequested-selector`, `uncited`, `malformed`,

every response in code-point order and counts rejected Brain candidates only;

Preserve the existing detector on every covered surface reached by complete
snapshot collection, including unselected tool-use records, and on selected
vendor/founder provenance when skill refs are selected. Run both detector sets
on query, hint, and every Brain string before output. A finding in a covered

optional Brain candidate
excludes only that candidate with `secret-material` and adds one bounded

Derive at most one sanitized diagnostic example per rejected candidate; for
