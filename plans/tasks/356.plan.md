# Issue #356 implementation plan — record canonical portable work evidence (Revision 3)

## Revision 3 (round-3 Codex convergence)

Changes per blocker:

1. **Merge order is tracker-resolved.** Issue #356 now carries `forge:blockedBy=381,350,370` plus a schema-order note. Stated plainly below and in Sequence/Risks: **#356 merges after #370; `013` is implemented and tested on top of `012`**, with an explicit 011→012→013 upgrade-sequence test (ledger exact-ordered-prefix rule, `src/lib/persistence/migrate-core.ts:175-198`).
2. **Broker content verification without pgcrypto.** Brokers no longer trust caller fingerprints. Each broker takes the caller's **canonical record text** (the exact `canonicalSourceJson` bytes the TS layer fingerprints) as its single payload parameter, stores it in a bounded control-free `record_canonical text` column on the parent row, and detects conflicts on the existing branch by **byte equality of stored vs supplied canonical text — zero hashing in SQL**. Every typed column (except server-derived `workspace_id`/`recorded_at`) is a jsonb **projection of `record_canonical`** extracted inside the broker, so columns (including embedded `action_digest`/`summary_hash`) can never disagree with the canonical bytes. Stored `record_fingerprint` columns are **removed**; fingerprints are TS-derived metadata recomputable from `record_canonical` (tested). Brokers additionally perform direct-call input validation (jsonb shape/exact-key/cardinality/identity/vocab checks) with stable RAISE codes, and wrap the body in `EXCEPTION` blocks re-raising type/CHECK/FK violations as the same stable codes so TS maps deterministically.
3. **Advisory lock key made executable and NUL-free.** The `\0`-framed scheme is dropped (PostgreSQL `text` cannot contain NUL). Locks use a **length-prefixed frame**: `hashtextextended(domain || ':' || length(c1)::text || ':' || c1 || ':' || length(c2)::text || ':' || c2 …, 0)` — injective without delimiter ambiguity. One definition, used identically in SQL, TS docs, and a parity test.
4. **Promotion identity fixed.** (a) Uniqueness over the nullable composite uses **per-kind partial unique indexes** (version-neutral) rather than `UNIQUE NULLS NOT DISTINCT` — CI is `pgvector/pgvector:pg16` (`ci.yml:17`) so PG15+ syntax would pass CI, but `spec/SPEC.md` promises "any compatible PostgreSQL" (`spec/CONTEXT.md:233`) and partial indexes avoid raising the floor. (b) `promotion_id` derives from the **stable identity only** (`evidence_kind` + composite evidence ids + `promoted_source_version_id`), never the full request — a conflicting re-promotion of the same identity with different content hits the existing row and fails on canonical-text comparison instead of minting a new row. **Multiple promoted source versions per evidence item are allowed** (each `promoted_source_version_id` is a distinct identity); the read side returns an ordered array.
5. **Promotion recovery contract specified.** Session-scoped advisory lock held across both effects (precedent `workspace-authority.ts:358`, `:406-421`); ingest-first (idempotent by #381's durable-intent design), then lineage insert (idempotent by derived `promotion_id` + canonical compare); crash between effects converges on re-run; explicit failpoint test (fail after ingest, before lineage; re-run; assert single source version + single lineage row). Promotion bytes are derived from an **exact canonical projection of the stored evidence row** (specified verbatim below) so re-promotion is byte-stable, and the expected `source_version_id` is pre-derivable via `prepareSourceIdentity` (`src/lib/brain/source-identity.ts:132`).
6. **Contract contradictions resolved.** (a) `HumanDecisionInput` gains `privacy` + `trust` (and for uniformity all four record kinds now carry `privacy_class` + `trust_class` `NOT NULL`). (b) The static-boundary assertion is narrowed to an allowlist: `evidence-store.ts` is the only `src/` module performing `brain_evidence` DML/content SELECT; `roles.ts` and `doctor.ts` may reference the schema name for grants/audit lists.

### 2. Canonical text, fingerprints, and the broker verification model (blocker 2)

- TS normalizes input → produces **`record_canonical`** = `canonicalSourceJson(normalizedRecord)` — one canonical byte string per record. This is simultaneously (a) the broker payload, (b) the stored conflict-detection value, and (c) the preimage of the TS fingerprint.
- **Fingerprints are derived metadata, not stored columns.** `record_fingerprint = 'sha256:' + sha256(domain-separated(record_canonical))` with domains `roster.brain.evidence.{completed-run|run-artifact|feedback|human-decision|promotion}.v1` (style of `source-identity.ts:12-15`). Return envelopes and `readCompletedRun` compute them from `record_canonical`; `verifyEvidenceRecord` recomputes fingerprint, `action_digest`, and `summary_hash` from the stored canonical text and flags any divergence (a direct broker caller embedding a forged digest produces a detectable-invalid record and can never silently collide with the honest record, whose replay byte-compares canonical text and conflicts loudly).
- **Broker contract** (one per record kind, `SECURITY DEFINER`, `SET search_path = pg_catalog, brain_evidence, brain_meta, pg_temp`, `REVOKE EXECUTE … FROM PUBLIC`):

```sql
brain_evidence.record_completed_run(record_canonical text)
  RETURNS TABLE (status text, id text)
-- likewise record_run_artifact / record_feedback / record_human_decision
```

Body, in order:
1. **Direct-call validation with stable codes:** byte cap + cast `record_canonical::jsonb` (failure ⇒ `RBE01`); exact-key set per kind via `jsonb_object_keys` count + `?` membership; array cardinality caps (`sources`/`tools` ≤ 64); identity grammar regexes; closed-vocabulary membership; `related_artifact ⇒ related_run`. All failures `RAISE … USING ERRCODE = 'RBE01'`.
2. Derive `workspace_id` from `brain_meta.workspace_identity` and `recorded_at` from the server clock — caller cannot supply either.
3. Advisory lock per §3.
4. `INSERT` parent row — **every typed column a jsonb projection of `record_canonical`** (`(record_canonical::jsonb)->>'field'`), plus the `record_canonical` column itself — `ON CONFLICT (pk) DO NOTHING`.
5. Created branch: insert child rows (run: `sources[]`/`tools[]` projected element-wise with ordinals) in the same transaction; return `('created', id)`.
6. Existing branch: `SELECT record_canonical` of the stored row; **byte-equal** ⇒ `('existing', id)`; different ⇒ `RAISE … USING ERRCODE = 'RBE02'` — transaction aborts, zero mutation. Children need no per-child comparison: the run's canonical text covers sources + tools.
7. **Outer `EXCEPTION` mapping** so even unanticipated constraint trips surface deterministically:

```sql
EXCEPTION
  WHEN foreign_key_violation THEN
    RAISE EXCEPTION 'referenced evidence row does not exist' USING ERRCODE = 'RBE03';
  WHEN check_violation OR not_null_violation OR invalid_text_representation
    OR string_data_right_truncation OR numeric_value_out_of_range THEN
    RAISE EXCEPTION 'evidence payload violates the closed schema' USING ERRCODE = 'RBE01';
```

Stable SQLSTATE → TS mapping (on `pg` error `.code`): `RBE01 → BRAIN_EVIDENCE_INPUT_INVALID`, `RBE02 → BRAIN_EVIDENCE_IDEMPOTENCY_CONFLICT`, `RBE03 → BRAIN_EVIDENCE_REF_NOT_FOUND`, `RBE04 → BRAIN_EVIDENCE_INTEGRITY` (`RosterError` shaped like `source-lifecycle.ts:144-166`).

### 3. Advisory lock scheme (blocker 3) — single definition, SQL/TS parity

```sql
-- frame(domain, components):
--   frame := domain;
--   for c in components: frame := frame || ':' || length(c)::text || ':' || c;
PERFORM pg_advisory_xact_lock(hashtextextended(frame, 0));
```

Length prefixes make the framing injective with no NUL (PostgreSQL `text` cannot hold NUL) and no delimiter ambiguity. Components: run → `[run_id]`; artifact → `[run_id, artifact_id]`; feedback → `[feedback_id]`; decision → `[decision_id]`; promotion → `[evidence_kind, coalesce(run_id,''), coalesce(artifact_id,''), coalesce(feedback_id,''), coalesce(decision_id,''), promoted_source_version_id]` (absent components encode as zero-length, still unambiguous). Domains: `roster.brain.evidence.lock.{run|artifact|feedback|decision|promotion}.v1`. Record brokers use `pg_advisory_xact_lock`; **promotion uses the session form** (`pg_advisory_lock`/`pg_advisory_unlock` on a dedicated verified client, unlock verified in `finally` — precedent `workspace-authority.ts:358`, `:406-421`) because it spans multiple transactions. The identical frame grammar is documented in `evidence-identity.ts` and pinned by a parity test that evaluates the SQL expression against the TS-declared frame for fixed vectors.

### 6. Store operations (`src/lib/brain/evidence-store.ts`)

- `recordCompletedRun/RunArtifact/Feedback/HumanDecision(pool, input)`: normalize → `record_canonical` → `SELECT * FROM brain_evidence.record_x($1)` → map `RBE*` codes → `{ status, id, recordFingerprint }` (fingerprint TS-computed from the canonical text).
- `readCompletedRun(pool, runId)`: run envelope + ordered `sources[]`/`tools[]` + aggregated `artifacts[]` + `feedback_ids[]`; fingerprints recomputed from stored `record_canonical`.
- `readHumanDecision`, `readPromotions(evidenceRef)` (ordered by `recorded_at, promotion_id` — multiple promoted source versions allowed per evidence item), `verifyEvidenceRecord(kind, envelope)`.
- **`promoteEvidence(adminPool, objectStore, request)` — recovery contract (blocker 5):**
  1. `SELECT` the referenced evidence row(s); absent ⇒ `BRAIN_EVIDENCE_REF_NOT_FOUND`.
  2. Build the **exact promotion projection** (byte-stable because `record_canonical` is immutable and excludes server-derived timestamp formatting):
     `promotionBytes = utf8(canonicalSourceJson({ domain: 'roster.brain.evidence.promotion-content.v1', evidence_kind, identity: { run_id?, artifact_id?, feedback_id?, decision_id? }, record: JSON.parse(record_canonical) }))`.
  3. Build the deterministic ingest input: `kind: 'structured-record'`; `stableKey = 'evidence-promotion:' + hex(domain-hash of the evidence identity)`; `requestKey = 'evidence-promotion:' + hex(promotion_id preimage hash)`; labels/privacy/trust from the request; provenance forced to carry `promoted_from = { evidence_kind, …ids }`. Pre-derive the expected `source_version_id` via `prepareSourceIdentity` (`source-identity.ts:132`), then derive `promotion_id` from the **stable identity** `{ evidence_kind, run_id?, artifact_id?, feedback_id?, decision_id?, promoted_source_version_id }` (blocker 4b).
  4. Acquire the **session** advisory lock on the promotion frame (§3) on a dedicated verified client; hold across both effects; release + verify in `finally` (`workspace-authority.ts:406-421` pattern).
  5. Effect 1: `ingestBrainSource` (`source-lifecycle.ts:759-784`) — idempotent by durable intent; assert the returned `sourceVersionId` equals the pre-derived one (else `BRAIN_EVIDENCE_INTEGRITY`).
  6. Effect 2: lineage insert in its own short transaction — `INSERT … ON CONFLICT (promotion_id) DO NOTHING`; existing branch byte-compares stored vs supplied promotion `record_canonical`: equal ⇒ `existing`; different (e.g. same identity, different provenance/actor) ⇒ idempotency conflict without mutation.
  7. **Crash between effects converges on re-run** because both effects are individually idempotent under the same derived identities. A retry after a completed effect 1 returns `existing` from ingest and `created` from lineage.
- Record verbs remain pure-Postgres (no object-store dependency); complete S3 config is still structurally required by the authority fingerprint.
