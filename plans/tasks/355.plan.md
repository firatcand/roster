## 4. Design decisions

**D1 — Do NOT route `roster context` through `resolveBrainActivationConfig`; pin the divergence instead of claiming equivalence.** *(Endorsed rounds 2-3; unchanged.)*

`test/static-boundaries.test.ts:394` carries the comment "#355 reuses this predicate for `roster context`", and `plans/tasks/383.plan.md:586` says the same. The answer is **no**, for the same TOCTOU reason as Revision 1: `resolveBrainActivationConfig` performs its own `readRegistryText` (`brain-activation-config.ts:73-98`) — a second, unsnapshotted read of `roster.yaml` outside `withAsyncContextReadCapability`'s session (`workspace-registry.ts:1554`) and outside `capability.verify`, reintroducing a window between the activation decision and the bundle's `workspace.source_hash`.

The two paths implement deliberately opposite precedence rules:

- The helper runs the structural probe `classifyBrainDeclaration` first (`brain-activation-config.ts:113-117`) and returns `incomplete` for any structurally partial block **without strict-parsing present values** — the probe's own comment says why (`workspace-record.ts:413-416`).
- The context path strict-parses via `parseBrainConfig`, which validates **every present value first** and only then reports the gap (`workspace-record.ts:359-363`): "a schema error outranks it." Pinned by `test/workspace-context.test.ts:2983-3014`.

Divergent case matrix (each cell verified against the two implementations):

| Input | `resolveBrainActivationConfig` | context path | Agree? |
|---|---|---|---|
| no `brain` block | `absent` | `brain_configured: false` + `BRAIN_NOT_CONFIGURED` | yes |
| complete, well-formed | `complete` | authority minted (`workspace-registry.ts:1385`) | yes |
| partial, present values well-formed | `incomplete(declaration)` | `YAML_INVALID` + `brain_configuration:'incomplete'` → `BRAIN_CONFIGURATION_INCOMPLETE` (`workspace-context.ts:3067-3082`) | yes |
| fully present, a malformed value | strict parse at `:118` throws `YAML_INVALID` | `YAML_INVALID`, no discriminator | yes |
| **partial + malformed present value** | `incomplete(declaration)` — probe short-circuits | discriminator-free `YAML_INVALID` (test `:2983-3014`) | **no** |
| **partial + unknown field** (incl. retired `brain.binding`, `workspace-record.ts:348-355`) | `incomplete(declaration)` | `UNKNOWN_FIELD` | **no** |

**Why not the shared-pure-classifier extraction?** A shared structural classifier already exists — `classifyBrainDeclaration` (`workspace-record.ts:417-432`) — and the divergence is not accidental drift but two opposite precedence rules, each shipped, each documented in code (`:359-363` vs `:413-416`), each pinned by tests. Crucially, the divergence is **contained and safe**: in both divergent rows, both paths refuse before contacting any store — only the diagnostic code differs — so "partial configuration contacts neither store" (spec/CONTEXT.md, Security invariants) holds on both sides.

`spec/SPEC.md:383` is the governing rule: "per-candidate diagnostics are optional examples and **fixed budget counters remain authoritative**." **The five scalars** (appended after `candidate_diagnostics_omitted` in `ContextBudget`, `workspace-context.ts:276-293`, and threaded through `buildBudget`, `:2390-2424`), all `number` except #5:

**D4.1 — Scope-ineligible (a category of its own — neither stale nor conflicting).** A lesson with the target's `scope.function`/`scope.agent` whose `scope.plan` names a plan outside the resolved closure (exactly `sibling-prior`) is *valid policy for another plan*. **D4.2 — Duplicate (AC-1's "deduplication"), with honest comparator reporting.** Two selected lessons whose **projected `body` strings are byte-identical** are the same guidance under two identities. **D8 — Exact, authoritative pre-assembler filter accounting, with a pinned index-preserving formulation (rewritten per round-3 blockers 3-5).**

What the code does today (verified): `accountFiltering` (`context-retrieval.ts:484-538`) runs a separate bounded query — `ORDER BY chunk_id LIMIT FILTER_ACCOUNTING_LIMIT` (512, `:36`, `:525-526`, bound at `:530`) — whose membership predicate is one `tsv @@ websearch_to_tsquery` over the *globally joined* selectors + query + stepHint text (`:490-494`, applied `:524`): truncated (≤512 rows), mis-scoped (blind to structured-only matches; over-approximating lexical membership by folding in query/stepHint), and — the round-3 finding — even a "fixed" global join would be *lossy*, because `boundedText` (`:222-231`) halves any string over `MAX_QUERY_TEXT_BYTES` (32,768, `:38`), so concatenating many per-selector segments into one bounded string can silently drop selectors that the arms, which bound **per selector** (`:238-242` via `:312`), still evaluate. The exact formulation therefore mirrors the arms' per-selector structure:

1. **Exact aggregates over a deduplicating union of the arms' own membership predicates.** Replace the single-predicate bounded subquery with:

   ```sql
   SELECT reason, count(*)::text AS entries FROM (
     SELECT CASE …                       -- the existing :498-511 CASE, verbatim
            END AS reason
       FROM (
         SELECT chunk_row.chunk_id       -- lexical membership, per selector
           FROM unnest($2::text[]) AS sel(member_text)
           JOIN brain.source_chunks chunk_row
             ON chunk_row.tsv @@ websearch_to_tsquery('english', sel.member_text)
         UNION                           -- deduplicates on chunk identity
         SELECT chunk_row.chunk_id       -- structured membership, per jsonpath
           FROM unnest($3::text[]) AS sel(json_path)
           JOIN brain.source_extractions member_extraction
             ON member_extraction.structured @? sel.json_path::jsonpath
           JOIN brain.source_chunks chunk_row
             ON chunk_row.extraction_id = member_extraction.extraction_id
       ) member
       JOIN brain.source_chunks chunk_row ON chunk_row.chunk_id = member.chunk_id
       JOIN brain.source_extractions extraction_row  -- existing :514-516, verbatim
         ON extraction_row.extraction_id = chunk_row.extraction_id
        AND extraction_row.status = 'complete'
       JOIN brain.source_versions version_row …      -- existing :517-518
       JOIN brain.logical_sources source_row …       -- existing :519-520
       LEFT JOIN brain.active_extractors active_row … -- existing :521-523
   ) accounted
    WHERE reason IS NOT NULL
    GROUP BY reason
   ```

   `$1` stays the label allowlist (consumed by the CASE's scope-ineligible `EXISTS`), `$2` is **the same per-selector membership array the lexical arm already passes** (`selectorMembershipText` per selector, `:312`/`:333` — one tsquery per selector, each bounded per selector exactly as the arm bounds it, never re-joined), `$3` is **the same (selector, jsonpath) enumeration the structured arm builds** (`:350-357` from `structuredJsonPaths`, `:263-267`), `$4` stays `includeLegacyUnverified`. `UNION` (not `UNION ALL`) deduplicates on chunk identity across arms *and* across selectors within an arm, so a chunk matching both arms — or five selectors — is classified and counted exactly once. No `ORDER BY`, no `LIMIT`; `FILTER_ACCOUNTING_LIMIT` is deleted (`:36` — consumer-free, confirmed round 3) and the `:34-36` header comment is rewritten: *an exact accounting, never a selection input*. The statement runs on the same client inside the same repeatable-read snapshot as the arms, so exactness is snapshot-consistent and deterministic.

2. **Index preservation, pinned by test, not assumed.** Each membership subquery hits its own index: the lexical branch drives `source_chunks_tsv_idx` (GIN over `tsv`, `data/brain/schema/012_extraction_indexing.sql:85`) with one tsquery per unnested selector; the structured branch drives `source_extractions_structured_gin` (GIN `jsonb_path_ops`, `:60-62`, which supports `@?`).
