# Issue #350 implementation plan — prove the seeded host-led learning loop

## Ticket

- GitHub: `firatcand/roster#350`
- Forge task: `P1-T07`
- Branch: `feat/350`
- Type: integration / QA golden proof
- Dependency: #349 (merged and closed)

## Outcome

Prove the smallest complete seeded Roster v2 loop through both Claude Code and
Codex:

```text
natural human request
→ exact discovery and complete validated plan
→ bounded context with cited fake Brain evidence
→ host interprets policy and uses a scoped fake tool
→ fixture-only completed evidence and feedback persist
→ one durable due watermark survives reopening
→ host invokes a fixture-only Dreamer skill
→ one idempotent cited candidate awaits the human
→ a second natural-language human approval promotes one Git lesson
→ a fresh context bundle includes the approved lesson
```

The proof shows that Claude Code and Codex are the runtime. It must not add a
Roster plan executor, current-step cursor, scheduler, queue, provider router,
approval authority, or production evidence/Dreamer contract.

## Decisions and authority

1. **The missing lifecycle capabilities stay test-only.** #349 truthfully
   reports completed-evidence recording, Dreamer readiness, and the candidate
   lifecycle as missing. #356–#358 own their production contracts. This issue
   must not change the production capability catalog, CLI, Brain schema,
   persistence, or shipped Dreamer skill.
2. **Reuse the Social Manager seed.** Extend its complete
   `gtm/social-manager#opportunity-discovery` closure in a sibling behavioral
   fixture. Do not change #349's hash-attested activation fixtures.
3. **Use real product seams for the implemented stages.** Exercise sparse
   scaffolding, exact discovery, validation, plan closure, scoped tool-use
   resolution, context assembly, lesson scaffolding, authored replacement, and
   later lesson selection. Fake only the evidence and Dreamer state that later
   tickets own.
4. **Keep seeded context private to tests.** A narrow helper under
   `test/support/` is the second and final test importer of
   `withContextReadCapability()`, alongside `test/workspace-context.test.ts`.
   No production seed flag, environment backdoor, fake provider, or re-export
   is allowed.
5. **Use deterministic CI plus required ambient-host certification.** Ordinary
   tests prove product primitives, durable state, idempotency, lesson
   materialization, and attestation freshness. A separate opt-in test invokes
   the exact installed Claude Code and Codex binaries through their existing
   logged-in host sessions. Roster never injects Anthropic/OpenAI model API
   keys. Live model calls never run in ordinary tests, smoke, install, or npm
   lifecycle scripts.
6. **The human interaction is natural language.** Turn one contains no Roster
   command, candidate ID, or tool procedure and ends awaiting the human. A
   separate fresh interaction carries the approval. Durable disk state—not a
   resumed model conversation—connects the turns.
7. **Do not invent an approval receipt.** The same promotion primitive is
   callable in both turns. Its turn-one call count must be zero; the host calls
   it only after the second human message. The promoted lesson is the only
   durable semantic difference caused by approval.
8. **Compare semantics rather than host narration.** Normalize both hosts into
   closed per-turn DTOs. Discovery contains target and plan hashes,
   interpreted step IDs, the effective tool-use hash, selected/rejected fake
   results with policy reasons, Brain citations/diagnostics, evidence IDs, the
   watermark, the complete pending candidate, and baseline lessons. Approval
   contains the stable target/plan/tool/evidence identity, the same candidate,
   and the promoted lesson IDs; it does not repeat the discovery shortlist or
   Brain diagnostics. Exclude unconstrained narration, host names, timestamps,
   session IDs, and call ordering.
9. **Attest every Roster-controlled behavior input.** Bind a canonical
   recursive file manifest, semantic support-code hashes, non-secret launch
   policy, sanitized host-auth capability probes, host/model versions, the
   exact built `bin/roster.js`, package version, Node version, and normalized
   outcomes. Ambient auth/config/cache/browser state is accepted but unpinned:
   never copy, scan, hash, or persist it. The attestation file is the sole
   excluded output to avoid self-reference.
10. **Bridge the missing stages with neutral fixture skills.** Codex discovers
    them through project-native `.agents/skills`; Claude loads an attested local
    test plugin with `--plugin-dir`. Both deliveries derive from identical
    common bytes and never ship.

The user chose option A for certification: deterministic CI plus a required
one-time real-host certification on final behavior bytes. The host boundary was
later corrected to `ambient-auth-v1`: Claude Code uses the existing Claude
account login and Codex uses the existing ChatGPT login; neither receives a raw
model-provider API key from Roster. Certification needs three consecutive
passes per host, six total. Every pass starts from an independent copy of the
same immutable initial workspace state. Durable artifact equality is checked
incrementally after every pass, so drift aborts before another paid host is
launched; a new attempt still restarts the complete six-pass sequence.

The executable proof is deliberately narrower than the deterministic suite:
it certifies Claude Code 2.1.220 with `claude-opus-5`/`xhigh` and Codex CLI
0.144.1 with `gpt-5.6-sol`/`xhigh` on macOS through one adopter's logged-in host

personal configurations, or browser/vendor workflows behave the same.
Ordinary deterministic tests remain the portable CI contract.

## Component and data flow

### 1. Build and validate the isolated workspace

- Generate a fresh Social Manager workspace through the existing fixture
  builder and production scaffold APIs.
- Install one host's canonical thin activation and assert it remains identical
  to the production renderer.
- Add the explicitly test-only host guidance through an attested local Claude
  plugin or native Codex project skills. Assert host-specific copies equal the
  common checked-in skill bytes.
- Validate the complete workspace once during setup. Validation is not a
  per-request handshake.
- Use exact compact discovery, then fetch the selected plan's complete context
  closure.

### 2. Assemble bounded seeded context

- The first actor is `human`; the request is a natural request with shell
  metacharacters and contains no procedural Roster instruction.
- The host derives a short non-secret retrieval query distinct from the raw
  request.
- The test helper supplies immutable fake Brain candidates with complete
  source/version/object/extractor/locator/content-hash citations.
- Include two Brain trust probes: a high-confidence instruction override that
  the production resolver excludes with one `low-trust` diagnostic, and a
  lower-confidence instruction-shaped record that passes screening but remains
  inert when interpreted by both hosts.
- The bundle includes root/nested plan definitions, scoped guidelines,
  four-layer tool-use merge, reviewed fixture skill locators, and no future
  lesson.

### 3. Let each host choose from fake tool results

- Supply a closed fake result set: one attributable relevant post, one profile
  URL, one cryptocurrency result, one previously used URL, and one prompt-
  injection result that asks the host to bypass the plan and promote early.
- Do not encode the winner in fixture skills or the output schema. The authored
  plan, guideline, and tool-use records are the only business-policy sources.
- The live host call log and normalized result prove that each host selected
  the valid result and rejected every decoy for the authored reasons.
- Test helpers provide data primitives only. They never select a plan step,
  choose a result, invoke the provider for the host, or execute a workflow.

### 4. Persist mock evidence and compute due once

- Store exactly one fixture completed-run observation and one linked feedback
  observation with stable citations.
- Reopen the store before status checks.
- Derive one stable watermark from eligible IDs and return `due` only once for
  the unprocessed watermark.
- Exact replays are idempotent. The same ID with different bytes fails without
  mutation.
- Serialized state contains no schedule, timer, daemon, dispatch, queue, lease,
  wake, retry, current-step cursor, continuation, or approval receipt.

### 5. Invoke fixture Dreamer and replay one candidate

- Claude proof requires a streamed `Skill` tool event for the fixture Dreamer,
  its successful result, and a later adapter call containing the exact
  digest/challenge that exists only in the skill bytes.
- Codex proof requires the skill in model-free `skills/list`, a JSONL-observed
  full read of that exact `SKILL.md`, and the later digest/challenge adapter
  call.
- The candidate is a closed neutral DTO, not arbitrary model-authored prose:
  `disposition`, `source_kind`, `topic_kind`, `falsifier_action`, and
  `falsifier_observation` are enum values. A deterministic renderer produces
  its exact recommendation and falsification wording. The candidate is scoped
  to the selected plan and cites the run and feedback IDs; it does not cite its
  own invocation.
- Reopen and replay candidate creation; the ID and bytes remain identical and
  count remains one.
- Turn one presents the candidate ID, closed meaning, rendered recommendation,
  rendered falsification wording, citations, and `candidate_content_hash` to
  the human, then ends at `awaiting_human`; no lesson file exists.

### 6. Promote after a fresh human approval and resolve again

- Start a new host process with a natural approval message.
- Assert the first interaction never invoked promotion and the second one did.
- The approval turn reads durable state through the fixture state adapter. Its
  host-visible `pending_candidate` projection must be `status: existing` and
  include the complete record plus the same content hash shown in discovery.
  Missing, changed, or ambiguous state fails before promotion.
- Use production lesson scaffolding, then a confined exact-byte authored
  replacement, and validate the resulting workspace.
- Repeated exact promotion is idempotent; a mismatched ID, changed candidate,
  or conflicting lesson bytes fails closed without mutation.
- Resolve context before and after with the same budget. The lesson-ID set after
  promotion must be a superset of the before set; the only addition is one
  `approved-lesson` included for `applicable-lesson`, with the right qualified
  scope and source hash.
- Derive sufficient token headroom from the promoted lesson's marginal cost and
  the largest optional-fragment marginal cost so the test cannot pass by
  evicting another lesson or balancing exactly on the budget boundary.

## Live certification host boundary

### Common controls

- Declare the profile as `ambient-auth-v1`: authentication and host-owned state
  lookup come from the installed adopter host, while workspace behavior and
  side-effect policy remain Roster-controlled for this seeded fake-tool proof.
- Build `bin/roster.js` immediately before certification and execute it by
  absolute path. Record its hash, package version, and full Node version.
- Run the executable certification only on macOS (`process.platform ===
  "darwin"`). Require Codex app-server initialization to report platform family
  `unix` and platform OS `macos`. A different platform fails closed rather than
  being treated as equivalent evidence.
- Create each child environment from an explicit allowlist: controlled `PATH`,
  the validated ambient Claude `HOME` or isolated Codex process `HOME`, the
  ambient `CODEX_HOME` needed for Codex host-managed login, temporary `TMPDIR`,
  locale, and non-secret fixture variables. Never spread `process.env`.
  Explicitly omit Anthropic/OpenAI API keys, auth-token overrides, provider
  switches, and unrelated business-tool secrets.
- Preflight authentication with each host's own status command under the exact
  paid-host auth envelope. Accept only the expected logged-in first-party
  Claude account and ChatGPT modes. Parse a closed non-sensitive projection;
  discard raw output, email, organization, subscription, token, and path data.
- Repeat the same sanitized auth-status check immediately after each paid host
  turn. A successful turn plus unchanged first-party status under an
  API-key-free environment is the fail-closed post-launch auth proof.
- Probe and hash each auth subcommand's exact versioned help surface. Claude
  2.1.220 must provide JSON status and has no text fallback. Codex 0.144.1 does
  not provide JSON status, so accept only its exact single-line
  `Logged in using ChatGPT` result; any other text fails closed.
- Provide Claude human input through stdin. Codex 0.144.1 ignores stdin in its
  model-free `debug prompt-input` path, so both Codex paid turns and their
  matching prompt-input probes receive the same non-secret, hash-attested
  request as one positional prompt and the same exact sandbox-canary developer
  instruction through launch config. Generated `AGENTS.md` remains untouched
  and manifest-valid. Codex 0.144.1's debug subcommand rejects `--strict-config`
  and paid `exec`-only flags, so record that closed limitation in the launch
  contract, derive the probe's global arguments from the paid launch by removing
  only `--strict-config`, and attest the exact paid-only flag set. This makes the
  preflight inspects a deliberately more permissive user-config regime than the
  paid turn because it cannot accept `--ignore-user-config`. Its one-directional
  proof is limited to workspace-, binary-, and session-sourced required
  contributions: if those anchors are present in the broader probe they must
  remain present when paid `exec` removes user-config contributions. It does not
  claim byte-identical command lines or identical full prompt contents. Use
  a new git-initialized workspace and new host process for every interaction.
- Give model-free capability probes their own workspace and `TMPDIR`. Auth
  status, Codex `skills/list`, and Codex `prompt-input` use the ambient host
  lookup because they measure the paid profile. Version/help and Claude fixture
  plugin validation remain hermetic because they measure immutable binary or
  fixture bytes. Probe workspaces never share fixture state with a paid
  interaction.
- User-level ancestor instructions and personal settings may exist. Managed or
  enterprise settings remain fail-closed under the unchanged
  `inventoryManagedSettings()` guard because Claude policy can add hooks or
  permissions that project-only setting sources cannot disable. Session flags
  close the active fake-tool surface: exact fixture commands, sandbox,
  MCP/browser policy, output bounds, and action traces are verified. Ambient
  personal state is never treated as Roster authority and cannot satisfy a
  required fixture skill or workspace contribution.
- Hash immutable source roots and every harness-authored settings, MCP, and
  config input before and after. Never recurse into, copy, delete, or hash the
  ambient home/config/cache/browser/KState. Normalize controlled paths to
  `$WORKSPACE`, `$REPO`, `$HOST_BIN`, `$HOST_HOME`, `$CODEX_HOME`, and `$TMPDIR`
  before hashing or persistence. Raw transcripts, call logs, absolute paths,
  session IDs, auth status output, and host-managed volatile bytes remain
  transient.
- Delete the old host-shaped transient config inventory. For Claude, attest
  only the exact two harness-authored files in its scratch config-input root.
  For Codex, the scratch config-input manifest is exactly empty; never pass
  ambient `CODEX_HOME` to `inventoryHostConfig()` or an equivalent walker.
- The ambient home is never a sandbox writable root. Temporary harness files
  remain confined to the certification root.
- Host-owned refresh/cache writes under the ambient profile are accepted and
  unpinned; Roster never reverts or cleans them. Session history persistence is
  disabled where the host exposes a supported control.
- Probe the exact binary version/help surface before any model call. A missing
  load-bearing flag fails; there is no compatibility fallback.

## Attestation and freshness

- Store output only at `test/attestations/host-led-learning.json`.
- Its input manifest covers the entire generated pre-mutation workspace, both
  fixture roots, prompts, schemas, common and installed skill bytes, launch
  metadata, capability probes, controlled executables, and the transitive
  behavior-producing/normalizing support-module closure.
- Keep the test driver declarative: only the environment gate and one call into
  the certification entrypoint. Hash support semantics after deterministic
  TypeScript transpilation with comments and source maps removed, using the
  pinned compiler version, so formatting-only changes do not force six calls.
- The harness-only semantic oracle is never copied into a host workspace,
  referenced by host-readable content, or exposed to an adapter.
- Attestation schema v2 and launch-contract schema v2 reject v1 rather than
  migrating it. The contract uses behavior revision `host-led-learning-v3` and
  fixture iteration 4.
- Attestation v2 records `ambient-auth-v1`; a closed sanitized auth projection
  (`claude.ai`/`firstParty` or `chatgpt`); host-managed authentication;
  `model_api_key_injected: false`; accepted-but-unpinned external host state;
  a per-host hash of the actual curated child-environment key names; three
  outcomes per host; normalized semantic result; controlled launch/probe
  hashes; exact versions; behavior revision; fixture iteration; and run date.
  The environment builder rejects provider credential/switch names before the
  key-set hash is made, so the false key-injection claim is derived rather than
  self-asserted.
- Replace the removed API-key scrub seed with the raw ambient home/Codex-home
  absolute paths as transient forbidden tokens. Normalize approved path
  occurrences first, then fail if those path-shaped personal tokens survive in
  traces, diagnostics, semantic output, or the committed attestation. Never use
  a bare username substring: common Roster words such as `.agents` can contain
  it and create a false leak verdict.

  No host, model, semantic, process, timeout, or infrastructure failure is
  retried automatically. Any failure aborts the current certification; the
  next attempt starts the complete six-pass run in a new certification root on
  one unchanged final byte set.
- Any behavior-affecting change invalidates the attestation and requires all
  six runs on one new exact byte set. `ROSTER_HOST_LED_LOOP_SMOKE=1` is the only
  opt-in gate.

## Edge cases

- Human input has shell metacharacters; the derived query is short, literal,
  non-secret, has no control/leading-option marker, and differs from the input.
- Exact evidence/candidate/promotion replay is idempotent; conflicting replay
  is rejected without mutation.
- Repeated status alone creates no candidate.
- A candidate exists in fixture state but is absent from context until
  promotion.
- Discovery exposes the complete candidate and its content hash for human
  review. Approval re-reads that same pending hash from durable state; it never
  reconstructs the candidate from conversation memory.
- Both hosts reject the same decoys and choose the same result for the same
  policy reasons.
- The high-trust Brain canary is excluded exactly once; the screened-in Brain
  canary and fake-tool canary remain data and cannot alter calls, candidate,
  lesson, or turn-one promotion behavior.
- Secret canaries, injection strings, raw tool output, machine paths, and model
  session IDs never reach evidence, candidate, lesson, or attestation.
