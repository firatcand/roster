## Contracts and data flow

### 0. Activation capability and write authority

`src/lib/brain/activation.ts`:

- `BrainActivation` is a frozen, **branded** type (unique-symbol brand; not literal-constructible):
  `Readonly<{ pool: VerifiedBrainPool; objectStore: BrainObjectStore & BrainObjectReader; [brand]: true }>`.
- Single constructor `requireBrainActivation({ pool, objectStore })`:
  1. requires both arguments (missing store → `BRAIN_EXTRACTION_ACTIVATION_INCOMPLETE`);
  2. asserts `objectStore.namespaceFingerprint === pool.authority.namespaceFingerprint` (pattern `source-lifecycle.ts:192-199`) → else `BRAIN_EXTRACTION_NAMESPACE_MISMATCH`;
  3. carries a **lazily evaluated, cached `adminPreflight`**: before the first mutation of any write API it probes `SELECT has_table_privilege(current_user, 'brain.source_extractions', 'INSERT')` (the `reindex.ts:53-59` pattern) and fails closed with `BRAIN_EXTRACTION_ADMIN_REQUIRED` when the connection lacks write authority. Read-only APIs never trigger the preflight.
- **Authority matrix (stated plainly):**
  - Write APIs — `extractBrainSourceVersion`, `reindexBrainExtractions`, `ensureEmbeddingSpec`, `reindexChunkEmbeddings` — expect a `VerifiedBrainPool` built from the ambient **admin** credential (`ROSTER_BRAIN_ADMIN_URL` pattern, exactly as the bootstrap/test path does today: `test/brain-source-lifecycle.test.ts:198-214` builds its verified pool on the admin-derived URL). The 012 tables are runtime-protected, so a runtime-credential pool physically cannot INSERT them; the preflight converts that into a stable early diagnostic instead of a mid-operation SQL error.
  - Read surfaces — `brain.current_source_chunks` (view; runtime SELECT via `roles.ts:385-388`) and `selectCurrentChunkEmbeddings(activation, embeddingSpecId, bounds)` (parameterized query function over SELECT-granted tables/views) — work under the runtime role (`ROSTER_BRAIN_URL`).
  - #383 wires actual command exposure and may later broker writes; no SECURITY DEFINER broker is introduced here.

### 1. Extractor contract (pure, deterministic)

- Closed compiled registry: `roster-text` v1 (UTF-8 text/markdown; heading/paragraph chunking adapted from `mount.ts:95-126`, fixed-window fallback) and `roster-structured` v1 (strict-JSON structured-record rendering). Identity = `(extractor_name, extractor_version int)`.
- Support is a pure function of `source_versions.media_type` + decoded content; refusals use closed reasons `media-type | invalid-utf8 | binary | too-large`.
- Bounds: decoded text cap 4 MiB; chunk content 1–8,192 chars / ≤ 16,384 bytes; `chunk_index` 0..65,535; locators `{byte_start, byte_end, line_start, line_end}` into the exact immutable object bytes plus `content_sha256`. Locators are byte-exact under multibyte UTF-8, CRLF, and BOM inputs (BOM preserved in byte accounting); structured rendering records the byte/line range of the source JSON it rendered.
- Deterministic IDs via the 011 canonical-JSON domain digest (`source-identity.ts:38-40`):
  - `extraction_id = digest('roster.brain.source-extraction.v1', {source_version_id, extractor_name, extractor_version})`
  - `chunk_id = digest('roster.brain.source-chunk.v1', {extraction_id, chunk_index})`

### 2. Additive schema — `012_extraction_indexing.sql` DDL sketch

```sql
-- Active-extractor registry. Admin-owned; runtime has no direct grant — the
-- current view reads it with owner privileges. Version bumps ship as later
-- migrations (monotone-increase guard trigger; no delete/truncate).
CREATE TABLE brain_meta.active_extractors (
  extractor_name text PRIMARY KEY CHECK (extractor_name ~ '^[a-z0-9]+(-[a-z0-9]+)*$'
    AND octet_length(extractor_name) BETWEEN 1 AND 80),
  active_version integer NOT NULL CHECK (active_version >= 1)
);
INSERT INTO brain_meta.active_extractors (extractor_name, active_version)
  VALUES ('roster-text', 1), ('roster-structured', 1);

CREATE TABLE brain.source_extractions (
  extraction_id text PRIMARY KEY CHECK (extraction_id ~ '^sha256:[a-f0-9]{64}$'),
  source_id text NOT NULL,
  source_version_id text NOT NULL,
  -- object identity derives via the composite FK join to source_versions
  extractor_name text NOT NULL CHECK (extractor_name ~ '^[a-z0-9]+(-[a-z0-9]+)*$'
    AND octet_length(extractor_name) BETWEEN 1 AND 80),
  extractor_version integer NOT NULL CHECK (extractor_version >= 1),
  status text NOT NULL CHECK (status IN ('complete', 'unsupported')),
  unsupported_reason text CHECK (unsupported_reason IN
    ('media-type', 'invalid-utf8', 'binary', 'too-large')),
  chunk_count integer NOT NULL CHECK (chunk_count BETWEEN 0 AND 65536),
  text_sha256 text CHECK (text_sha256 IS NULL OR text_sha256 ~ '^[a-f0-9]{64}$'),
  structured jsonb CHECK (structured IS NULL OR (jsonb_typeof(structured) IN ('object','array')
    AND octet_length(structured::text) <= 262144)),
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (source_version_id, extractor_name, extractor_version),
  UNIQUE (extraction_id, source_version_id),
  FOREIGN KEY (source_id, source_version_id)
    REFERENCES brain.source_versions(source_id, source_version_id),
  CONSTRAINT source_extractions_status_shape CHECK (
    (status = 'complete' AND unsupported_reason IS NULL AND text_sha256 IS NOT NULL)
    OR (status = 'unsupported' AND unsupported_reason IS NOT NULL
        AND chunk_count = 0 AND text_sha256 IS NULL AND structured IS NULL))
);
CREATE INDEX source_extractions_structured_gin
  ON brain.source_extractions USING gin (structured jsonb_path_ops)
  WHERE structured IS NOT NULL;

CREATE TABLE brain.source_chunks (
  chunk_id text PRIMARY KEY CHECK (chunk_id ~ '^sha256:[a-f0-9]{64}$'),
  extraction_id text NOT NULL,
  source_version_id text NOT NULL,
  chunk_index integer NOT NULL CHECK (chunk_index BETWEEN 0 AND 65535),
  content text NOT NULL CHECK (octet_length(content) BETWEEN 1 AND 16384),
  content_sha256 text NOT NULL CHECK (content_sha256 ~ '^[a-f0-9]{64}$'),
  byte_start bigint NOT NULL CHECK (byte_start >= 0),
  byte_end bigint NOT NULL CHECK (byte_end > byte_start),
  line_start integer NOT NULL CHECK (line_start >= 1),
  line_end integer NOT NULL CHECK (line_end >= line_start),
  tsv tsvector GENERATED ALWAYS AS (to_tsvector('english', content)) STORED,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (extraction_id, chunk_index),
  FOREIGN KEY (extraction_id, source_version_id)
    REFERENCES brain.source_extractions(extraction_id, source_version_id)
);
CREATE INDEX source_chunks_tsv_idx ON brain.source_chunks USING gin (tsv);
CREATE INDEX source_chunks_version_idx ON brain.source_chunks (source_version_id, chunk_index);

-- Immutable spec registry (SPEC conceptual name, SPEC.md:473). No ann_index_name,
-- no lifecycle state: rows never change, so the plain reject-mutation trigger
-- applies without exceptions. ANN indexes are #352's measured migration work;
-- #370 embedding reads are exact-only. Dimensions above HNSW's per-vector index
-- limit are simply not ANN-indexed — moot here, recorded for #352.
CREATE TABLE brain.embedding_indexes (
  embedding_spec_id text PRIMARY KEY CHECK (embedding_spec_id ~ '^sha256:[a-f0-9]{64}$'),
  provider text NOT NULL CHECK (provider ~ '^[a-z0-9][a-z0-9._-]*$'
    AND octet_length(provider) BETWEEN 1 AND 128),
  model text NOT NULL CHECK (octet_length(model) BETWEEN 1 AND 255 AND model !~ '[[:cntrl:]]'),
  dimensions integer NOT NULL CHECK (dimensions BETWEEN 1 AND 4096),
  spec_version integer NOT NULL CHECK (spec_version >= 1),
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (provider, model, dimensions, spec_version)
);

CREATE TABLE brain.chunk_embeddings (
  chunk_id text NOT NULL REFERENCES brain.source_chunks(chunk_id),
  embedding_spec_id text NOT NULL REFERENCES brain.embedding_indexes(embedding_spec_id),
  dimensions integer NOT NULL CHECK (dimensions BETWEEN 1 AND 4096),
  embedding vector NOT NULL,                 -- dimensionless (Decision 1 resolved)
  created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (chunk_id, embedding_spec_id),
  CONSTRAINT chunk_embeddings_dims_match CHECK (vector_dims(embedding) = dimensions)
);
-- No ANN index in this migration (exact-only in #370).

-- Defense in depth (secret never embedded + spec/dims agreement):
CREATE FUNCTION brain.guard_chunk_embedding_insert() ...  -- raises when the chunk's
  -- source_version has privacy_class = 'secret' or embedding_indexes.dimensions
  -- disagrees with NEW.dimensions
CREATE TRIGGER chunk_embeddings_guard_insert BEFORE INSERT ON brain.chunk_embeddings ...;

-- Immutability: reuse brain.reject_source_lifecycle_mutation() (011:318) for
-- UPDATE/DELETE/TRUNCATE on all four brain.* tables; brain_meta.active_extractors
-- gets its own monotone-version-bump-only guard.

-- Current chunks: select the ACTIVE version first, then require complete —
-- a missing/unsupported active-version extraction is an explicit gap,
-- never stale-v1 exposure.
CREATE VIEW brain.current_source_chunks AS
  SELECT c.*, e.extractor_name, e.extractor_version,
         v.source_id, v.privacy_class, v.trust_class, v.media_type, v.object_id
    FROM brain.source_chunks c
    JOIN brain.source_extractions e ON e.extraction_id = c.extraction_id
    JOIN brain_meta.active_extractors a
      ON a.extractor_name = e.extractor_name
     AND a.active_version = e.extractor_version
    JOIN brain.source_versions v ON v.source_version_id = e.source_version_id
    JOIN brain.logical_sources s
      ON s.source_id = v.source_id
     AND s.current_version_id = v.source_version_id
     AND s.active_tombstone_id IS NULL
   WHERE e.status = 'complete';
-- No current_chunk_embeddings view: the embedding consumption surface is the
-- spec-parameterized query function.

INSERT INTO brain_meta.runtime_protected_tables (table_name) VALUES
  ('source_extractions'), ('source_chunks'), ('embedding_indexes'), ('chunk_embeddings');

REVOKE ALL PRIVILEGES ON brain.source_extractions, brain.source_chunks,
  brain.embedding_indexes, brain.chunk_embeddings FROM PUBLIC;
REVOKE ALL PRIVILEGES ON brain_meta.active_extractors FROM PUBLIC;
```

### 3. Extraction write path (`src/lib/brain/extraction.ts`) — admin-path

1. All entry points take `BrainActivation`; every write API awaits the cached `adminPreflight` before its first mutation (§0).
2. **Registry drift check**: on first SQL use per activation, compare the compiled extractor registry constant against `brain_meta.active_extractors`; mismatch fails closed with `BRAIN_EXTRACTION_REGISTRY_DRIFT` and a migrate remedy.
3. `extractBrainSourceVersion(activation, { sourceVersionId, bytes? })`:
   - loads the immutable version row plus its `source_objects` row (media type, privacy, `sha256`, `size_bytes`, `s3_version_id`);
   - **uniform byte verification, one stored form**: computed raw-hex digest of the bytes must equal `brain.source_objects.sha256` (`011_source_lifecycle.sql:12`) **and** `bytes.byteLength` must equal `size_bytes` — applied identically to caller-supplied bytes and to reader-fetched bytes; failure → `BRAIN_EXTRACTION_OBJECT_UNVERIFIED`. Absent bytes are fetched via `readVerified({ sha256, byteLength, versionId: s3_version_id ?? undefined })` (bounded stream + digest check; missing/corrupt → explicit failure, never fabricated, per `source-recovery.ts` policy);
   - runs the pure extractor; in one transaction inserts the extraction row + all chunks with `ON CONFLICT DO NOTHING`, then asserts stored-row equivalence (pattern `source-lifecycle.ts:530-570`): divergent replay → `BRAIN_EXTRACTION_INTEGRITY_CONFLICT`; identical replay converges; a per-extraction advisory lock (`source-lifecycle.ts:221-223`) serializes races.
4. `reindexBrainExtractions(activation, opts)`: batched scan of current, non-tombstoned versions lacking an active-version extraction row; per-item extraction with per-batch commits → resumable; deterministic IDs + conflict-free reinsert → idempotent. Report: `{ targeted, extracted, unsupported, failed, remaining }`.
5. Error family: `BRAIN_EXTRACTION_ACTIVATION_INCOMPLETE | BRAIN_EXTRACTION_NAMESPACE_MISMATCH | BRAIN_EXTRACTION_ADMIN_REQUIRED | BRAIN_EXTRACTION_REGISTRY_DRIFT | BRAIN_EXTRACTION_INPUT_INVALID | BRAIN_EXTRACTION_SOURCE_NOT_FOUND | BRAIN_EXTRACTION_OBJECT_UNVERIFIED | BRAIN_EXTRACTION_INTEGRITY_CONFLICT` via `RosterError` (pattern `source-lifecycle.ts:144-166`).
6. No change to `ingestBrainSource` signatures or transaction boundaries; a thin composed helper forwards in-memory bytes (re-verified per step 3) for the ingest-then-extract flow #383 will expose.

### 4. Optional embeddings (`src/lib/brain/embedding-provider.ts`, `embedding-index.ts`) — exact-only

- Provider-neutral `EmbeddingProvider { provider; model; dimensions; specVersion; embed(texts): Promise<number[][]> }`. **No named adapter in #370**; the resolver takes an injectable adapter registry (empty in this ticket) and reads the existing non-secret `embeddings.*` config keys (`src/lib/brain/config.ts:7-20`).
- **Closed resolution outcome**: `{ status: 'resolved'; provider } | { status: 'disabled' } | { status: 'credential-unavailable' } | { status: 'invalid-configuration'; reason }` — never throws (posture of `embed.ts:89-95`); carried verbatim in reindex reports.
- `ensureEmbeddingSpec(activation, provider)` — admin-path, activation-gated — **only registers** the immutable `brain.embedding_indexes` row (provider/model/dimensions/version, the acceptance metadata) with `ON CONFLICT DO NOTHING` + equivalence read-back. No index DDL of any kind.
- `reindexChunkEmbeddings(activation, resolution, opts)` — admin-path: non-`resolved` outcomes return immediately with `{ embeddings: resolution.status, targeted: 0, ... }` and touch no state. When resolved: targets current chunks (via `brain.current_source_chunks`) with `privacy_class <> 'secret'` and no row for the spec; batches ≤ 96 (`reindex.ts:5`); `ON CONFLICT DO NOTHING` inserts with per-batch commits → resumable, idempotent; provider failure aborts with counters + sanitized cause, no partial row, rerun converges; a spec change targets only the new spec.
- `selectCurrentChunkEmbeddings(activation, embeddingSpecId, bounds)` is the #352 consumption surface (parameterized query function; exact scan filtered by spec, joined through `current_source_chunks` so superseded/tombstoned/other-spec vectors can never surface). Works under the runtime role.
- Secret exclusion triple-enforced: SQL target predicate, batch-assembly assertion, 012 insert trigger.
