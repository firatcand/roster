### 4.2 Immutable-version identity discipline

Source-version ids are minted per hermetic database, so the gold set never records a version id. Instead (blocker 2, honest layering):

- The fixture records the **raw body** for every revision; the harness asserts at ingest time that the resolved version's `object_id` equals `'sha256:' + sha256(rawBody)` (raw-body identity — `source_objects`, `011_source_lifecycle.sql:10–27`). This is the acceptance criterion's "relevant immutable source versions", satisfied by content addressing plus derive-don't-restate resolution (`ingestCorpusSource`'s return, `brain-retrieval-corpus.ts:144–159`).
- **Chunk-level content hashes are a different object**: citation `content_hash` covers the *extracted chunk content* (`content_sha256`, DB-enforced by trigger `012_extraction_indexing.sql:156`), which for structured records is a rendered projection and legitimately differs from any raw-body slice. Gate families may pin `expectedChunkContentSha256s` per revision (computed at authoring by running the same extraction), and the citation-completeness gate independently re-verifies `sha256(candidate.content) == content_hash` at delivery time, so recording them is a fixture-integrity aid, not the proof.
- **Supersession needs multiple versions per logical source**, so `fixtureVersionKey ≠ sourceStableKey`: one logical source (`sourceStableKey`) carries an ordered list of revisions, each with its own `fixtureVersionKey`; the harness ingests them in order and retains **every** ingest result in a `fixtureVersionKey → {sourceId, sourceVersionId, chunkIds}` map, so a query can reference the *superseded* revision explicitly (as an expected exclusion) and the harness can assert the exact version id that must not be delivered.

Eligibility is modeled as THREE ORTHOGONAL explicit expectations on every referenced item (round-2 blocker 2 — the earlier "four-way classification" left label/scope implicit, letting a scope or privacy exclusion masquerade as a membership miss): `expectSelectorClaim: true|false` (+ `expectedSelectors`/`expectedArms` when true), `expectLabelScopeEligible: true|false` (+ `expectedLabelKeys`/`expectedScope`), and `expectPolicyEligible: true|false` (+ `reason` when false). A RELEVANT item is {claim: true, labelScope: true, policy: true}; a DELIBERATE MEMBERSHIP MISS is {claim: false, labelScope: true, policy: true} — and the harness VERIFIES the miss is genuinely membership-only by DIRECT item-keyed adminPool assertions (round-3 blocker 1: the accounting SQL selects membership-REACHABLE chunks before applying filter reasons — context-retrieval.ts:509 — so an unreachable chunk yields empty buckets regardless of its eligibility, and bucket-absence proves nothing): for each miss item the harness queries the ingested rows and asserts, mirroring the eligibility predicates WITHOUT the membership predicate, that its labels satisfy the request's scope allowlist, its privacy class is compatible, its version is current (not superseded/tombstoned), its trust class is admissible under the request's opt-in, and its extraction is active — 'active' mirroring `current_source_chunks`'s own definition: registry version match AND `status = 'complete'` (round-4 note) — proving label/scope/policy eligibility directly so only the missing selector claim explains its absence; a POLICY-FILTERED item is {policy: false} with its exact reason asserted in the accounting. Every `membershipMisses` entry carries `expectedLabelKeys`/`expectedScope` so its label/scope eligibility is asserted, not assumed.

### 4.4 Query families (the discriminating design)

Size target ~45–65 queries over ~90–130 sources, one shared corpus per tier (one `createFreshDb` + ingest pass serves everything). **Truncation bound (blocker 5):** for gate families the authoring rule is that the **total** number of corpus chunks matching each selector's membership text — relevant, irrelevant, and incidental alike — is ≤ `PER_SELECTOR_ARM_LIMIT` (8), so in-arm truncation can never confound a gate; the authoring self-check (§8) enforces this with a per-selector count query over the ingested corpus, not by trusting the author.

1. **baseline** (~12 q, GATED): documents whose wording overlaps the selector descriptions; text + structured records; expected Recall@64 = 1.0. The "measure lexical+structured baseline FIRST" family every deferred ticket's disposition anchors on.
2. **exclusion** (~9 q, GATED): per-reason constructions covering **all six** reasons — superseded (second revision of a `sourceStableKey`), tombstoned (`tombstoneBrainSource`), secret privacy, scope-ineligible labels, `legacy-unverified` with and without the opt-in, and **extractor-inactive** (a dedicated fixture extraction inserted with a non-active `extractor_version` via adminPool, registry untouched — the round-1 bump technique breaks activation before accounting runs, per round-2 blocker 1) — asserting both non-delivery and the exact `filtered` accounting (the `context-live-brain.test.ts:215–290` pattern at eval scale).
3. **precedence** (~5 q, GATED; corrected per round-2 blocker 3 — a delivered eligible chunk has `reason = NULL` and never appears in `filtered`, so "delivered AND counted once" was impossible): (a) TWO separate dual-arm fixtures — a DELIVERED chunk reached by both arms through two different selectors (assert exactly one candidate, `retrieval_modes` containing both arms, `selectors` equal to the sorted union, and NO `filtered` entry for it) and a deliberately FILTERED dual-arm chunk (e.g. tombstoned content matching both arms' membership — assert it appears in `filtered.tombstoned` exactly ONCE, which is the accounting-side `UNION` dedup proof, `FILTER_ACCOUNTING_SQL` comment lines 485–487); (b) retrieval-label correctness — exact `selectors`, exact `label_keys`, and exact derived `scope` (narrowest claim) asserted against `expectedSelectors`/`expectedLabelKeys`/`expectedScope`; (c) the **structured `@object:` citation proof** — for a `roster-structured` candidate assert region `object`, the byte range spanning the full source document, `sha256(candidate.content) == content_hash`, *and* that the immutable object bytes at `object_id` hash to `object_id` itself — demonstrating the two-hash topology (raw-body identity vs rendered-content hash) rather than pretending one hash serves both.
4. **alias-variant** (~10 q, MEASURED, feeds #329): documents naming an entity by a variant of the selector-description/query term — abbreviation, hyphenation/spacing, casing beyond tsvector normalization, misspelling, true synonym — recorded as `deliberate-membership-miss` items sub-tagged by `missClass`. The corpus also carries the **canonical↔alias ground truth**: entities via `insertMergeFixtureEntities` plus `brain.entity_aliases` rows (adminPool insert, precedent `test/brain-canonical-index.test.ts:52`) mirroring the fixture's `aliases` section. Two measurements per query: (a) **baseline miss rate** (vocabulary-mismatch evidence — this alone shows tsvector's limits, *not* alias benefit); (b) the **alias-expansion ORACLE** (blocker 4): re-run the same query with each selector's descriptions augmented by the alias expansions the alias table returns for the canonical entities that selector names (a plain `lower(alias)` join read via adminPool), and report the **counterfactual recall delta**. That delta is the honest ceiling of KNOWN-ALIAS EXPANSION on the existing substrate, measured without building the arm — it is NOT a ceiling for a fuzzy trigram arm, whose match quality (partial/misspelled forms outside the alias table) remains unmeasured and is named as such in the #329 section (round-2 blocker 4).
5. **multi-record** (~8 q, MEASURED, feeds #330/#332): relevant set = {anchor record, linked record} where the link is only an identity reference inside structured bodies (the relation a one-hop traversal would follow); the linked record is a `deliberate-membership-miss` (`missClass: "linked-record"`). Joint recall vs anchor-only recall quantifies the **one-hop** graph recall gap. This family is explicitly **one-hop only**; §6.3 states the multi-hop/cycle/fan-out/precision/latency dimensions as insufficient-evidence-pending-#397 with named measurements.
6. **ordering / paraphrase-ordering** (~11 q, MEASURED, feeds #331/#333): membership guaranteed (docs match selector descriptions) but the *query* wording is paraphrased/disjoint so `ts_rank_cd` ordering is stressed; several relevant items per query with graded relevance. Measures MRR/NDCG@10 and the oracle reordering headroom — a **common ceiling** for embeddings-as-rescorer and reranking alike (§1 fact 2).

### 4.5 Gate vs measurement discipline

Only baseline, exclusion, precedence, citation, determinism, latency, privacy, and reproducibility families/properties gate. Alias-variant, multi-record, and ordering families are measurements — gating them would convert optional capabilities into launch requirements, violating acceptance criterion 5.

## 5. Metric definitions (exact formulas, in the README and report; blocker 3)

**Unit rule (applied to every ranking metric):** relevance is authored at **source-version** level; delivered candidates are chunks. Before any ranking metric, the delivered list is **collapsed to source versions by first occurrence**: walk `D(q)` (candidates ordered by `retrieval_rank`), keep a candidate only if its `citation.source_version_id` has not appeared earlier, drop later duplicates entirely (they are neither relevant nor irrelevant — they are the same version again). Call the collapsed ordered list `Dv(q)` and its first `k` elements `Dv@k(q)`. `R(q)` = the fixture-resolved relevant source-version ids (the union of `relevant` and, for gap measurements, `membershipMisses`); `X(q)` = expected-excluded version ids.

- **Recall@k(q)** = `|Dv@k(q) ∩ R(q)| / |R(q)|`; suite value = macro-average per family; k ∈ {8, 10, 64}. **Gate:** baseline family Recall@64 = 1.0. Alias/multi-record/ordering families report-only.
- **Precision@k(q)** = `|Dv@k(q) ∩ R(q)| / min(k, |Dv(q)|)` — denominator in the same (version) unit as the numerator; defined as `0` when `|Dv(q)| = 0` (round-3 note).
- **MRR** = mean over q of `1 / rank(first relevant in Dv(q))`, 0 if absent. Report-only.
- **NDCG@10(q)** = `DCG@10 / IDCG@10` with `DCG@10 = Σ_{i=1..10} rel(Dv_i(q)) / log2(i+1)` (rel = the authored grade of that version, 0 if not relevant) and `IDCG@10` from the descending-sorted grades of `R(q)`. Report-only.
- **Oracle reordering headroom@k(q)** = `min(|Dv(q) ∩ R(q)|, k) / |R(q)| − Recall@k(q)` — the exact gain a perfect reorderer of the *delivered* set could achieve: the capacity term (Revision 1's undefined "10-relevant-capacity") is now defined as `min(count of relevant versions anywhere in the delivered set, k)`. **Validity condition (round-2 blocker 4): the headroom bound is a true common ceiling ONLY when `truncated = 0`** — embedding scores participate in fusion BEFORE the 64-candidate cap (`context-retrieval.ts:830`), so under truncation an embedding rescorer could pull relevant pre-cap candidates into delivery and exceed the delivered-set bound. The ordering families' authoring rule therefore requires `truncated = 0` (enforced by the self-check), and the harness asserts it per ordering query; with that condition the bound is exact for both #331-as-rescorer and #333 (§6.5).
- **Exclusion correctness(q)** = 1 iff every `e ∈ X(q)` satisfies `version(e) ∉ Dv@64(q)` **and** the report's `filtered[reason]` equals the constructed chunk count for that reason (exact, per `FILTER_ACCOUNTING_SQL`'s closed six-reason contract). **Gate:** 1.0. (Accounting is chunk-denominated by contract; exclusion sets are version-denominated; both are stated as such — no unit mixing.)
- **Citation completeness** = (delivered candidates where all 7 envelope fields are present, `sha256(content) == content_hash`, and the locator proof holds — `@bytes` re-slice of the immutable object hashing to `content_hash` for `roster-text`; the §4.4-family-3 object proof for `roster-structured`) / `returned`. **Gate:** 1.0, in both the memory tier and the MinIO tier.
- **Determinism** = two consecutive `retrieveBrainContextEvidence` runs produce deep-equal evidence (telemetry excluded), and two metric computations over one evidence set are identical. **Gate.**
- **Reproducibility / independent rebuild (blocker 7)** = two **full ingest+measure cycles from scratch** (fresh database via `createFreshDb`, fresh object store — fresh MinIO bucket in the S3 tier) produce **identical result manifests** modulo the timing-sample and environment sections. **Gate.** This is strictly stronger than same-snapshot determinism: it proves the corpus build, ingest ordering, and metric pipeline are themselves deterministic.
- **Latency** = warm max-of-5 `telemetry.transactionMs` (+ `embedMs` when the arm runs) per family, **gate < 2000 ms** (SPEC.md:828); `connectMs` reported separately; the *scaled-corpus* 2 s proof is cited from acceptance 10 (`brain-context-retrieval.test.ts:2097–2231`) rather than duplicated. Report-only p95 over 30 runs on one representative query (`context.benchmark.ts` discipline).
- **Cost** (deterministic proxies; report-only): per-query `armRows` per mode, `pool`, `considered`/`returned`/`truncated`, statement count per code path, and for the fake-adapter run: embed invocations, stored vectors, bytes embedded. Byte-identical across the rebuild gate.
- **Privacy** (gates): zero `privacy: 'secret'` candidates in any delivery; zero `legacy-unverified` without opt-in; the hermetic lint (fixtures + generated artifacts) passes.

**The result manifest** (`docs/evals/retrieval-quality/2026-08-DD.json`, `schema_version: 1`): git commit + dirty flag (a `dirty: true` manifest is marked NON-AUTHORITATIVE in its own header and the report script warns), `fixtureSha256` (sha256 over the canonicalized fixture files), **harness identity as content hashes: per-file sha256 of the runner, metric, lint, and renderer modules as read at run time** (identifying uncommitted harness code exactly — round-2 blocker 6), effective config (`rrfK`, `TOTAL_CANDIDATE_LIMIT`, `PER_SELECTOR_ARM_LIMIT`, k values), `node` version, PG `server_version`, pgvector `extversion`, environment description ({ci|dev, os, s3Tier: memory|minio}), **tiered result sections** (`tiers.memory` and, when `HAS_S3`, `tiers.minio` — each with its own per-family and per-query metric rows), raw timing samples, and the five disposition inputs. **The rebuild-gate comparison projection is explicit:** manifests compare equal after removing a declared JSON-pointer exclusion list (`/environment`, `/timings`, per-tier `/timings`); the two-cycle schedule runs per tier — memory-tier double cycle in the PG-gated section, MinIO-tier double cycle (fresh bucket each cycle) in the S3-gated section. The dated Markdown is **generated from this manifest** by the report script; the Markdown is prose + tables, the JSON is the diffable ground truth.

1. **Alias search (#329).** Substrate: `entity_aliases` + trigram index exist (`005_dedup_merge.sql:14–24`), consulted only by dedup (`dedup.ts:68–76`), never by retrieval. Recommendation shape: keep-deferred with the oracle delta recorded and an activation threshold expressed against a representative adopter corpus ("activate if ≥ X % of entity-bearing queries fall in miss classes the oracle recovers"). 2. **Default embeddings (#331).** Substrate: adapter registry ships empty (`embedding-provider.ts:31–32`); the arm is **ordering-only** (`context-retrieval.ts:414–421, 848–850`) — it cannot repair a membership miss. Measured: (a) baseline membership recall (what embeddings cannot improve today); (b) ordering headroom (what they could); (c) one hermetic fake-adapter run (the parity-test seam, `brain-context-retrieval.test.ts:1590+`) measuring the arm's *mechanical* marginal latency/cost only. The report states plainly: synthetic vectors measure mechanics, not semantic quality; **the headroom is a ceiling shared with #333, so this evidence cannot choose between #331 and #333** — see §6.5 for the named deciders. Recommendation shape: defer; baseline sufficiency + measured headroom + the shared-ceiling statement.
3. **Graph expansion (#330).** Substrate: the cited engine hard-codes `graph: unavailable ['no-cited-edge-relation','unmeasured']` (lines 169, 922); edges carry no `source_version_id` (`001_init.sql:41–48`); #397 (blocked by parked #384) owns the fix. **New evidence (Revision 2):** an uncited one-hop expansion *implementation already exists* in legacy `search.ts:147–173` (consuming `search.graph_hops`), fail-closed at the CLI (`roster.ts:176`) and forbidden to the assembler (`static-boundaries.test.ts:313`) — so one-hop traversal MECHANICS already exist in-tree; their cost and quality are unmeasured (per-hop latency and fan-out are exactly the named deferred measurements), so no cheapness claim is made — the evidence is existence, and the gap is the citation substrate plus every unmeasured dimension below. Measured honestly now: the one-hop joint-recall gap from the multi-record family. Explicitly **insufficient evidence, defer pending #397**, for: multi-hop recall (hop = 2), cycle behavior, fan-out/pool-inflation distribution, expansion precision (fraction of hop-added versions that are relevant), and per-hop `transactionMs` cost — each named as the measurement #368 should require before activation. No fake graph measurements.
4. **Automatic edges (#332).** Structured as **defer-pending-named-measurements**: the multi-record table measures only the *demand* half (is there a recurring graph recall gap?). Unmeasured and stated so: edge-extraction recall/precision against a labeled edge gold set, lineage/citation preservation through extraction, privacy-class propagation (edges derived from secret content), and write-time cost/latency. Even a large measured demand defers behind #397 + #330, since auto-edges feed a retrieval arm that does not exist.
5. **Hosted reranking (#333).** Measured: precision@k, MRR, NDCG@10, and the oracle reordering headroom bound — with the explicit statement that this bound is **common to #331 and #333** and therefore *cannot decide between them*. What would decide it (named in the report): live-provider ordering quality on a representative adopter corpus under each option, the privacy delta (a hosted reranker ships candidate *content* across the trust boundary at query time; embeddings ship content at index time and the query at embed time — `spec/CONTEXT.md` privacy invariants), marginal latency against the 2 s budget (SPEC.md:828), and per-query cost. Recommendation shape: insufficient evidence; defer pending those named measurements, with the headroom bound recorded as the value ceiling either option chases.
